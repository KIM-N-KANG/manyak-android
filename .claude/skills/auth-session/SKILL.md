# 인증과 세션

## 경계

토큰 수명·회전·무효화·멀티 디바이스 정책은 서버 계약입니다. 합의되지 않은 값을 클라이언트 기본값으로 확정하지 않습니다.

## 인증 경로

- 서버 토큰 저장이 완료된 시점만 로그인 완료로 봅니다.
- 인증 요청은 하나의 공통 경로에서 토큰 첨부·갱신·실패 처리를 받게 합니다.
- 화면과 상태 홀더에는 토큰을 노출하지 않습니다.
- 401은 갱신 후보, 403은 권한 없음으로 구분합니다.
- 갱신 성공 뒤 원 요청 재시도는 한 번으로 제한합니다.

## 동시 갱신

여러 요청이 동시에 만료를 감지하면 하나만 갱신하고 나머지는 같은 결과를 기다리게 합니다. 갱신 요청 자체는 갱신 경로를 다시 타지 않습니다. 토큰 회전을 사용한다면 저장과 교체 순서가 동시 요청에서도 일관돼야 합니다.

## 저장과 복구

- 저장 방법은 위협 모델, OS 지원 범위, 백그라운드 접근 요구를 보고 결정합니다.
- 하드웨어 보호를 모든 기기에서 사용할 수 있다고 가정하지 않습니다.
- 보안 저장소 읽기 실패나 키 무효화 시 무한 시작 실패 대신 로컬 세션 정리와 재로그인 경로를 제공합니다.
- 앱에 포함된 값은 비밀로 간주하지 않으며 서버 비밀을 번들에 넣지 않습니다.

## 세션 종료와 노출

- 로그아웃, 계정 전환, 탈퇴의 서버 의미와 화면 전환을 구분합니다.
- 실제 로컬 삭제 대상은 `session-data-cleanup`이 탐색합니다.
- 로그·크래시·분석 이벤트·백업·알림·외부 입력에 토큰이나 사용자 원문이 노출되지 않게 합니다.
- 새 개인정보나 권한을 수집할 때만 목적, 보관 기간, 삭제 경로와 스토어 공시를 확인합니다.

## 결과와 검증

클라이언트 결정, 서버 합의 항목, 미결정, 노출 위험만 보고합니다. 프로젝트 공통 계약이 바뀔 때만 `docs/plans/_project.md`를 갱신합니다.

실행은 `android-change-verification`에 맡기고 필요한 경우 `auth-session` 또는 `session-cleanup` 위험 태그를 전달합니다.
