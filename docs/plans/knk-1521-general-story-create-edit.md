# KNK-1521 일반 제작과 스토리 수정

## 목표와 기준

[KNK-1521](https://kimandkang.atlassian.net/browse/KNK-1521)의 제작 방식 선택, 일반 제작 폼, 이미지 업로드, 임시 저장, 검수와 재제출 및 기존 스토리 수정을 연결합니다.

2026-10-05 기존 `feat/KNK-1521-general-story-create-and-edit` 브랜치를 재사용하고 최신 `origin/dev`로 fast-forward했습니다. Android 기준은 `668c1bdc`, 하네스 기준은 `ee58384`이며 KNK-1519, KNK-1520, KNK-1543을 포함합니다. 시작 시 남아 있던 이 조사 문서를 구현 계획으로 갱신합니다. Jira는 이미 진행 중입니다.

정본은 [공통 폼](../../../knk-harness/docs/spec/3-1-client-spec.md#fe-screen-009-일반-제작스토리-수정), [검증 규칙](../../../knk-harness/docs/spec/3-1-client-spec.md#3-1-8-입력폼-검증-규칙), [Android spec](../../../knk-harness/docs/spec/3-3-android-spec.md), [Android design](../../../knk-harness/docs/design/1-2-android-design.md)입니다. API는 당일 직접 조회한 [dev Swagger JSON](https://dev-api.manyak.app/v3/api-docs)과 서버 `StorySubmissionService` 및 `SubmissionFormAssembler`로 확인합니다.

## 확정한 선택

저장 방식은 사용자 요청으로 기존 테이블 확장, 별도 Room 테이블, 파일 저장을 다시 비교했습니다. 기존 간편 제작의 생성 명령과 복구 분기를 보존하기 위해 별도 테이블 추가를 추천했고 사용자가 확정했습니다.

- 기존 DB v4에 일반 제작 테이블만 추가하는 v5 마이그레이션을 사용합니다. 계정 ID와 초안 ID를 복합 키로 쓰고 버전 있는 폼 JSON과 처음 저장 시각을 보관합니다.
- 202 접수 시 편집 JSON을 제거하고 제출 ID만 남깁니다. 해당 행은 카드에 노출하지 않으며 이후 늦은 저장을 거절합니다. 복원된 초안 라우트는 이 제출 ID로 서버 입력을 읽습니다.
- 이미지는 앱 전용 파일에 고유 이름으로 보관합니다. 업로드 objectKey와 미리보기 참조를 폼에 기록하고 저장하지 않은 교체가 이전 저장본을 덮어쓰지 않게 합니다.
- 기존 `create` 안에 일반 제작과 수정의 모델, 변환, API 및 화면을 둡니다. 채팅 생성은 `common/ChatStarter`를 사용하며 새 Gradle 모듈을 추가하지 않습니다.
- Photo Picker와 Compose 고정 비율 크롭을 사용합니다. 실제 MIME 및 5MB 상한, 샘플링 디코딩, EXIF 보정 후 자르며 업로드 전용 OkHttpClient에는 인증과 분석 헤더를 붙이지 않습니다.
- 일반 제작도 버튼과 실제 백그라운드 전환에서만 저장하고 재개는 스토리 프로필 탭부터 시작합니다. 탭 이동과 구성 변경 및 선택기 왕복은 저장 계기가 아닙니다.

선택 이유는 [A-061과 A-062](../../../knk-harness/docs/adr/1-3-android-adr.md#a-061-일반-제작의-별도-초안-테이블과-제출-접수-경계)에 기록합니다.

## 실패와 복구 경계

- 신규 POST는 서버 멱등 키가 없습니다. 응답 유실을 성공이나 실패로 단정하지 않고 자동 재전송을 막습니다. 프로세스 종료까지 정확히 한 번 접수를 보장하지 않습니다.
- 접수한 제출 ID가 있으면 로컬 기록 실패 때문에 POST를 다시 활성화하지 않습니다. 접수 연결만 재시도하며 디스크 실패와 프로세스 종료가 겹친 복구 한계를 기록합니다.
- 화면의 STARTED 수명에서 검수 결과를 조회합니다. 대기 상한은 단조 시계 시작 시각을 보존하므로 회전으로 연장되지 않습니다. 화면 이탈은 조회만 취소하고 서버 검수는 유지합니다.
- 쓰기와 접수 기록은 ActivityRetained 수명으로 완료하고 owner 및 SessionGate 세대 검증을 통과한 결과만 반영합니다.
- 수정에서 서버 인물과 첫 이미지 외의 기존 이미지는 ID로 보존합니다. 알 수 없는 설정 글 절은 본문으로 보존하고 파서 기본값만으로 PATCH하지 않습니다.
- 표지 삭제와 PATCH는 원자적이지 않습니다. DELETE 성공 즉시 수정 baseline을 갱신하고 나머지 입력은 PATCH 실패 후에도 보존합니다.
- 성공한 등록과 수정은 제작 목록에 갱신 신호를 보냅니다. 폼을 먼저 닫고 접수된 요청도 반영하며 수정 복귀가 기존 조회와 겹치면 추가 조회를 예약합니다.
- 업로드 실패와 취소는 이전 이미지를 유지합니다. 재선택과 항목 삭제 뒤 도착한 응답은 작업 ID와 대상 존재 여부로 거절합니다.

## 검증 계획

위험 태그는 `db-migration`, `state-restore`, `idempotent-write`, `race-condition`, `coroutine-lifecycle`, `failure-recovery`, `ui-flow`입니다. `plan-critique` 기준으로 저장과 응답 유실 및 미표시 서버 데이터 보존을 검토했습니다. 가장 큰 외부 한계는 신규 등록 API의 멱등 키 부재입니다.

- 모델 및 요청: 설정 글 왕복, 알려지지 않은 절 보존, 필수와 중복 규칙, 소개 빈 값, 변경 필드 PATCH, 인물과 이미지 ID 유지 및 검수 경로 매핑.
- 저장: 실제 Room v1부터 v4까지 v5 마이그레이션과 기존 데이터 보존, 복합 키, 최초 저장 시각 및 접수 후 저장 거절.
- 화면 제어: 가상 시간으로 1초 조회 및 60초 상한과 취소, 타임아웃과 중복 요청 차단, 업로드 응답 순서, 저장 실패.
- 로컬 게이트: 변경 모듈의 컴파일, ktlintCheck, detekt, 직접 관련 단위 테스트, checkModuleArchitecture. 전체 check와 assembleDebug는 자동 반복하지 않습니다.
- 기기: installDebug 후 일반 제작 입력, 선검증 오류 이동, 저장 및 재개, 이미지 크롭, 회전과 다크 모드의 전후 캡처. 개발자 옵션 활동 유지 안 함을 확인하고 기기 설정은 복원합니다.

## 외부 의존과 제외

인물 소개 검수는 KNK-1512의 실제 AI 배포 확인이 필요합니다. 앱의 입력과 사유 매핑은 구현하지만 AI 검수 배포 여부를 앱 코드만으로 보장하지 않습니다.

게스트 진입, 웹 URL 직접 진입과 복수 이미지 관리는 제외합니다. 처음 제외했던 방식 선택 일러스트 애니메이션은 아래 웹 UI 정합에서 구현했습니다. 서버 인증이 필요한 dev 등록과 검수 시나리오의 실응답 검증 여부는 아래 실행 결과에 구분합니다.

### 웹 UI 정합

2026-10-05 웹 `dev`(`cc3747f`)의 일반 제작 화면과 비교해 배치, 문구 및 웹 전용 모션 차이를 맞췄습니다. 장르 선택은 앱이 먼저 반영한 제공 장르 검색 기준이며 웹은 같은 내용의 KNK-1542가 미병합 상태입니다. 웹 dev 폼은 로그인이 필요해 코드로 비교했고, 공개 화면인 제작 방식 선택은 브라우저 캡처와 비교했습니다.

- 헤더와 임시 저장은 간편 제작의 헤더와 버튼을 그대로 씁니다. 성공 토스트는 버튼이 띄우고 실패만 화면 메시지로 남깁니다. 수정 화면은 닫기만 둡니다.
- 모든 칸에 웹의 예시 placeholder와 설명을 넣고 설명과 오류를 14sp로 맞췄습니다. 여러 줄 칸은 줄 수 기준 최소와 최대 높이를 두고 넘치면 칸 안에서 스크롤합니다. 최소 턴 수는 글자 수 대신 단위를 붙입니다.
- 탭 줄은 시작 여백과 최소 폭을 없앴습니다. 주변 인물, 시작 상황, 주요 사건 탭은 접는 항목이 화면 끝까지 닿고 바닥 페이드를 겹칩니다. 접는 항목은 간편 제작과 같은 `CollapsibleInputSection`이며 하나 남은 인물은 삭제를 숨깁니다.
- 시작 상황은 둥근 칩과 둥근 추가 버튼, 하나의 추천 입력 묶음, 엔딩 안내를 웹 순서로 둡니다. 주요 사건은 제목과 안내를 둡니다.
- 등록 탭은 간편 제작의 장르 검색 콤보박스를 공유하고 공개는 `ManyakSwitch`, 주의 문구는 둥근 회색 상자로 바꿨습니다. 검토 안내도 같은 상자 모양을 씁니다.
- 이미지 칸은 마냑 심벌 미리보기, 이미지 추가와 변경, 삭제, 비율과 형식 안내로 바꿨습니다. 자르기는 바텀 시트의 검은 판 위에 비율 창과 3×3 격자를 그리며 최대 확대를 웹과 같은 3배로 낮췄습니다.
- 닫기 경고는 웹과 같은 상태별 문구를 쓰되, 사용자 요청으로 앱의 모든 확인 다이얼로그와 같이 머무르는 버튼은 "닫기"로 통일했습니다. 저장할 내용이 없을 때는 Android 계약대로 간편 제작과 같은 확인을 띄웁니다.
- 웹 전용 모션인 제작 방식 선택 일러스트 두 개와 분량 배분 인라인 슬라이더를 같은 시간과 곡선으로 구현했습니다. 동작 줄이기 설정에서는 완성 장면이나 즉시 이동을 씁니다.
- 제작 탭의 반려 카드 수정하기는 초안 카드의 이어서 만들기와 같은 버튼과 위치로 옮겼습니다.
- 사용자 요청으로 간편 제작 퍼널의 덮개 전환을 없애 제작 방식 선택에서 두 제작 화면이 같은 수평 이동으로 들어오고 나가게 했습니다. 입력한 것도 저장하거나 등록을 요청한 것도 없으면 간편 제작 세 단계와 일반 제작 모두 확인 없이 닫습니다([A-063](../../../knk-harness/docs/adr/1-3-android-adr.md#a-063-잃을-것-없는-제작-이탈과-제작-화면-전환-통일)). 화면 녹화로 진입과 이탈 전환 및 바로 닫기를 확인했습니다.
- 사용자 요청으로 검수 결과를 화면에서 기다리는 동안과 화면이 같은 결과를 보여 준 뒤 2분 안의 같은 제출본 검수 완료 알림을 띄우지 않게 했습니다. 알림은 서버 data 전용이라 앱이 표시 여부를 정하므로 서버 변경은 없습니다. `GeneralReviewWatchTest` 3개와 `ModerationNotificationUiTest`의 걸러진 알림 경우를 추가했습니다. 이 app 모듈 기기 테스트는 끝난 뒤 에뮬레이터의 앱을 제거해 로그인과 로컬 초안이 지워졌고, 앱은 다시 설치했습니다.
- 엔딩 최소 턴 수는 웹처럼 빈 칸으로 시작하고 비우면 필수 입력 오류를 띄웁니다. 범위는 0~50 그대로입니다. 검증 단위 테스트를 더했고 설치 앱에서 빈 칸 안내를 확인했습니다.

변경 모듈 `create`, `studio`, `designsystem`의 컴파일, ktlintCheck, detekt와 단위 테스트가 통과했습니다. create 단위 테스트는 슬라이더 계산 5개를 더해 205개입니다. `GeneralStoryFormUiTest` 기기 테스트 4개가 통과했습니다. 설치 앱에서 7개 탭, 엔딩과 사건 추가, 인물 삭제 확인, Photo Picker와 자르기 시트 및 실제 업로드, 임시 저장 토스트와 잠금, 저장 후와 빈 폼의 닫기 경고, 수정 화면 헤더, 방식 선택 일러스트 루프와 다크 모드를 캡처로 확인했습니다. 확인용 일반 초안은 삭제해 기존 간편 제작 초안 2개만 남겼고 다크 모드는 되돌렸습니다. 반려와 실패 검토 안내 및 반려 카드는 서버 상태가 필요해 코드로만 확인했습니다.
