# 간편 제작 이탈 가드·백그라운드 복구

> **KNK-1197 구조 이전 안내 (2026-09-05)** — 아래 모듈 경로·코드 예시·검증 명령은 작성 당시 기록입니다. 현재 소유 위치와 검증 결과는 [모듈 재구성 기록](./module-reorganization.md), 현재 계층·의존 규칙은 [하네스 모듈 아키텍처](../../../knk-harness/docs/planning/android-module-architecture.md)를 따릅니다.

- 공통 계약 정본: `../../../knk-harness/docs/product-specs/3-1-client.md` §3-1-4(이탈 가드·백그라운드 생성 복귀·제작 임시 저장, dev 병합 확인), `4-backend.md` §4-3-2 KNK-623 복구 계약(dev 병합 확인)
- 앱 결정 정본: `../../../knk-harness/docs/product-specs/3-3-android-app.md` §3-3-5 라이프사이클 절(이 계획으로 작성)

## 목표

- 생성·완성 요청 `requestId` 를 영속해 프로세스 재시작·앱 전환 후에도 복구 조회(3초 폴링)로 결과를 되찾는다.
- 퍼널 이탈 시 진행 내용을 임시 저장(`STORY_DRAFT`)하거나 진행 중 레코드를 유지하고 토스트로 알린다.
- 홈 상단 "이어서 만들기" 배너와 FAB 진입 시 이어서/새로 만들기 다이얼로그를 붙인다.
- 완성 재시도 409 를 실패가 아니라 복구 폴링으로 합류시킨다(수동 검증에서 확인된 409 고착 해소).

제외 범위(3-1 과 동일): 키워드 단계 저장, 강제 종료성 이탈 시점의 진행 스냅숏 저장, 서버 저장·기기 간 동기화, TTL.

> D1·D3·D6은 `create-funnel-exit-redesign.md`의 E14·E2·E9로 대체되었습니다.

## 외부 합의 필요

없음 — 서버 계약(KNK-623)은 구현 완료·dev 병합 상태다.

## 구현 단계

1. `core:domain` — 레코드 모델(`PendingStoryCreation`, stage 판별)·스토어 인터페이스·복구 조회 모델, `StoryCreationRepository.creationRequest(requestId)`.
2. `core:data` — DataStore 레코드 스토어(+`UserScopedStore` 바인딩), `GET stories/simple/creation-requests/{requestId}` API·DTO·매핑.
3. `feature:create` — 생성 스토어 확장(레코드 기록·복원·스토리라인 폴링·진행 미러), 키워드 이탈 처리+토스트, 스토리라인 Idle→복원 합류, 추가 정보 VM(스냅숏 재구성·409 폴링·storyId 승계·레코드 정리). (2 이후, 4·5와 병렬 가능)
4. `feature:home` — HomeViewModel(배너·진입 다이얼로그·폐기), 모듈 의존 추가(hilt·domain). (1 이후)
5. `app` — 재개 콜백 → 단계 체인 백스택 구성.
6. 문자열 리소스·단위 테스트.
7. 하네스 §3-3-5 결정 작성(구현 전 선행), 종료 후 매트릭스 갱신.

## 검증

- 태그: `idempotent-write`(409·requestId 영속), `state-restore`(프로세스 재시작 복원), `session-cleanup`(새 사용자 귀속 저장소), `data-retry`(폴링 도입)
- 실행: 변경 모듈 단위 테스트 + detekt/ktlint. 프로세스 재시작·백그라운드 복귀·로그아웃 정리는 수동 검증 항목으로 남긴다(에뮬레이터 세션 별도).
