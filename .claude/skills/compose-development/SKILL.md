# Compose 구현

## 구현 기준

- 프로젝트 테마와 공통 컴포넌트를 먼저 찾아 재사용합니다.
- 프로젝트의 UDF를 따라 화면은 불변 상태를 받고 사용자 이벤트를 콜백으로 올립니다. 이동·데이터 로딩과 상태 전이의 구체 구현을 직접 소유하지 않게 합니다.
- 화면 밖에서도 필요한 상태만 끌어올리고 컴포넌트 내부 표현 상태는 로컬에 둡니다.
- 네트워크 호출이나 상태 변경을 컴포저블 본문에서 직접 실행하지 않습니다.
- 효과의 키와 취소 수명을 실제 입력에 맞춥니다.
- Flow는 화면 생명주기에 맞춰 수집합니다.
- 목록에는 데이터의 안정된 식별자가 있을 때만 key를 지정합니다.
- 조작 요소의 의미, 상태, 터치 영역을 보조 기술이 이해할 수 있게 합니다.

기존 공통 컴포넌트의 공개 계약을 크게 바꿔야 할 때만 선택지를 사용자에게 확인합니다. 요청 범위 안의 국소 확장은 합리적인 기본값으로 진행합니다.

## Preview

Preview는 구현을 이해하거나 회귀를 발견하는 데 도움이 되는 대표 상태만 만듭니다.

- 새 화면: 기본 상태 하나
- 변경이 직접 영향을 주는 경우에만 오류·빈 상태·다크 모드·큰 글자·넓은 창 중 해당 상태 추가
- 테마와 화면 상태의 전체 조합은 만들지 않습니다.
- 반복 조합이 필요하면 parameter provider 등으로 중복을 줄입니다.

## 완료

변경 모듈을 컴파일하고 직접 관련된 UI 테스트가 있으면 실행합니다. 명령 선택과 추가 수동 확인은 `android-change-verification`에 맡깁니다.

지원 창 크기·지역화·접근성 정책 자체를 바꿔야 할 때만 `adaptive-ui`를 함께 사용합니다.
