# 테스트 우선 구현

## 목적

테스트를 먼저 써서 구현을 이끄는 작업 스킬입니다. 실제 테스트 파일을 만들고 Gradle task를 돌립니다.

무엇을 어디까지 테스트할지는 고려 사항 7번 항목 스킬에서 정합니다. 그 결정이 이미 있으면 따르고, 없으면 이 스킬이 정하지 않고 그쪽을 먼저 봅니다. 여기서는 **정해진 대상을 어떻게 테스트로 옮기고 실행하는지**를 다룹니다.

## 선행 전제: 실패를 보지 않은 테스트는 테스트가 아닙니다

통과하는 것을 확인하기 전에 **실패하는 것을 먼저 확인합니다.** 이 단계를 건너뛰면 아무것도 검사하지 않는 테스트가 통과하는 것을 보고 넘어가게 됩니다. 단언을 빼먹었거나, 잘못된 대상을 보고 있거나, 비동기 결과를 기다리지 않고 끝나는 테스트가 전부 여기서 걸립니다.

실패 메시지도 함께 봅니다. 기대한 이유로 실패해야 합니다. 컴파일 오류나 설정 문제로 실패한 것은 빨간불이 아니라 준비가 덜 된 것입니다.

## 적용 범위 판단

| 요청 | 하는 일 |
| --- | --- |
| 로직이 있는 기능 구현 | 행동 정의 → 실패 테스트 → 최소 구현 → 정리 |
| 재현되는 버그 수정 | 재현 테스트 먼저 → 실패 확인 → 수정 |
| 기존 코드에 테스트 추가 | 현재 동작을 고정하는 테스트부터 |
| 테스트가 불안정함 | 디스패처·시간·공유 상태부터 확인 |
| 리팩터링 | 기존 테스트가 그 경로를 덮는지 먼저 확인 |

## 무엇을 어떤 테스트로 옮기는가

| 대상 | 테스트 | 확인하는 것 |
| --- | --- | --- |
| 순수 로직, 변환, 계산 | 단위 테스트 | 입력에 대한 출력. 경계값과 빈 값을 포함합니다 |
| 상태 홀더 | 상태 전이 테스트 | 사건을 넣었을 때 상태가 어떤 순서로 바뀌는지 |
| 화면 | UI 테스트 | 사용자가 보는 것과 하는 것. 내부 구현이 아니라 semantics로 찾습니다 |

- **화면 요소를 구현 세부로 찾지 않습니다.** 텍스트나 접근성 레이블로 찾으면 레이아웃을 바꿔도 테스트가 살아 있고, 접근성도 함께 검증됩니다.
- **상태 전이는 최종 상태만 보지 않습니다.** 로딩을 거쳤는지, 오류 뒤 복구되는지가 사고가 나는 자리입니다.
- **테스트 이름에 조건과 기대를 적습니다.** 실패했을 때 이름만 보고 무엇이 깨졌는지 알 수 있어야 합니다.

## 코루틴과 시간

- **디스패처를 주입합니다.** 코드가 디스패처를 직접 고르면 테스트에서 바꿀 수 없고, 결과를 기다리려고 대기를 넣게 됩니다. 대기가 들어간 테스트는 느리고 불안정합니다.
- **시간을 테스트에서 제어합니다.** 지연이나 타임아웃이 있는 코드는 가상 시간으로 돌립니다. 실제 시간을 기다리면 테스트가 그 시간만큼 느려집니다.
- **불안정한 테스트를 재시도로 덮지 않습니다.** 대부분 디스패처를 제어하지 않았거나 테스트끼리 상태를 공유하는 문제입니다. 원인을 찾습니다.

## 회귀 버그

**고치기 전에 재현 테스트를 먼저 만듭니다.** 순서는 이렇습니다.

1. 버그를 드러내는 테스트를 씁니다.
2. **그 테스트가 실패하는 것을 확인합니다.** 실패하지 않으면 재현하지 못한 것이므로 수정에 들어가지 않습니다.
3. 고칩니다.
4. 테스트가 통과하는 것을 확인합니다.
5. 관련 테스트를 함께 돌려 다른 것을 깨지 않았는지 봅니다.

재현하지 못한 채 고치면 고쳤는지 알 수 없고, 같은 버그가 다시 와도 알아채지 못합니다.

## 작업 흐름

1. **요구사항을 확인 가능한 행동으로 바꿉니다.** "잘 동작한다"가 아니라 "무엇을 넣으면 무엇이 된다"로 적습니다. 바꿀 수 없으면 요구사항이 아직 모호한 것이므로 사용자에게 묻습니다.
2. **테스트 대상 결정이 이미 있는지 확인합니다.** 없으면 고려 사항 7번 항목 스킬을 먼저 봅니다.
3. **실패하는 테스트를 씁니다.** 한 번에 하나씩입니다.
4. **테스트를 돌려 실패를 확인합니다.** 기대한 이유로 실패하는지 봅니다.
5. **통과시키는 최소 구현을 합니다.** 지금 테스트가 요구하지 않는 것을 미리 만들지 않습니다.
6. **테스트를 돌려 통과를 확인합니다.**
7. **중복과 이름을 정리합니다.** 테스트가 통과하는 상태를 유지하며 고칩니다.
8. **관련 테스트를 전부 다시 돌립니다.** 범위 선택은 `android-change-verification` 스킬을 씁니다.
9. **실행한 명령과 결과를 그대로 보고합니다.** 통과했다고 적기 전에 출력을 봅니다.
