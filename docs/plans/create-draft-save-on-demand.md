# 간편 제작 임시 저장 개편 — 스냅숏 축적과 명시적 저장

> **KNK-1197 구조 이전 안내 (2026-09-05)** — 아래 모듈 경로·코드 예시·검증 명령은 작성 당시 기록입니다. 현재 소유 위치와 검증 결과는 [모듈 재구성 기록](./module-reorganization.md), 현재 계층·의존 규칙은 [하네스 모듈 아키텍처](../../../knk-harness/docs/planning/android-module-architecture.md)를 따릅니다.

- 공통 계약 정본: `../../../knk-harness/docs/product-specs/3-1-client.md` §3-1-4(이탈 가드·제작 임시 저장)
- 앱 결정 정본: `../../../knk-harness/docs/product-specs/3-3-android-app.md` §3-3-3(퍼널 chrome)·§3-3-5(라이프사이클)
- 선행 계획: `create-funnel-exit-redesign.md` — 이 계획이 그 문서의 E11·E19(300ms 자동 저장)·E20(뱃지)·E21을 대체한다

## 목표

- 선택·입력마다 디스크에 쓰던 300ms 디바운스 자동 저장을 없앤다. 편집은 메모리 스냅숏에 모아 둔다.
- 모아 둔 스냅숏은 **앱이 백그라운드로 갈 때(Activity `onStop`)** 한 번에 저장한다.
- 헤더의 임시 저장 뱃지를 **사용자가 직접 누르는 버튼**으로 바꾼다.
- 임시 저장하지 않은 변경을 두고 이탈하려 하면 무엇이 사라지는지 먼저 알린다.

## 새로 내린 결정

| # | 결정 | 근거 |
| --- | --- | --- |
| D1 | 편집(키워드 입력·선택 스토리라인·추가 정보 입력·추천 선택)은 메모리 스냅숏에만 모으고, 디스크 쓰기는 임시 저장 버튼과 `onStop` 두 경로에서만 일어난다 | 사용자 결정. 입력마다 Room을 쓰면 무엇이 언제 저장됐는지 사용자가 알 수 없고, 되돌리기 어려운 편집(입력 삭제)까지 말없이 확정된다. 저장 시점을 사용자가 쥔다 |
| D2 | 저장 시점의 라이프사이클 관찰 대상은 **목적지가 아니라 Activity** 다 | 목적지 수명은 퍼널을 떠나는 이동에서도 멈춘다. 목적지 `onStop`에 걸면 "저장하지 않고 나가기"까지 저장해 D5가 무의미해진다 |
| D3 | 생성·완성 **요청 레코드**와 **생성 성공 결과**는 지금처럼 즉시 저장한다 | 사용자 편집이 아니라 복구 계약(요청 `requestId`)과 다시 얻기 비싼 AI 결과다. `create-funnel-exit-redesign.md` E19의 이 부분은 유효하다 |
| D4 | 헤더 액션은 높이 40dp(`sizes.input`)의 회색 버튼(`button-neutral` 색 + 하단 "이전" 버튼과 같은 1dp `colors.border` 테두리)이다. 기본 라벨 `임시 저장`, 저장 중에는 라벨 자리에 스피너를 겹치고 잠그며, 성공하면 `backgroundBrandSubtle` 배경과 `textBrand` 아이콘·라벨(테두리 없음)로 체크 아이콘과 `임시 저장됨`을 2초 보여 준 뒤 기본으로 돌아간다. 저장 중과 `임시 저장됨` 표시 중에는 버튼을 잠근다 | 사용자 결정. 뱃지는 상태만 알려 주고 사용자가 저장 시점을 정할 수 없었다. 방금 저장한 것을 곧바로 다시 저장할 이유가 없고, 2초 뒤 기본으로 돌아가야 그 뒤의 편집을 다시 저장할 수 있음이 드러난다 |
| D5 | **저장하지 않은 변경이 없으면 버튼을 잠근다.** 판정은 키워드 단계가 `현재 스냅숏 != 마지막 저장 스냅숏`, 뒤 단계가 `생성 결과가 있고 · 진행 중 요청 레코드가 슬롯을 쥐고 있지 않고 · 지금 초안이 디스크에 그대로 있지 않음` | 눌러도 아무것도 바뀌지 않는 버튼은 저장이 안 된 것처럼 보인다. 입력을 모두 지운 것도 변경이라 그 상태에서는 눌리며, 저장하면 남아 있던 저장본이 함께 사라진다 |
| D5b | 뒤 단계의 잠금 판정에는 활성 탭까지 따지는 `draftPersisted` 를 쓴다 — 이탈 경고 판정(D8)이 활성 탭을 빼는 것과 다르다 | 탭을 옮기면 디스크와 갈리므로 저장할 것이 생긴다. 반면 그것만으로 이탈을 막을 이유는 없다. 같은 값을 두 판정이 다르게 보는 것이 의도다 |
| D6 | 이탈(헤더 닫기·시스템 뒤로가기)에 저장하지 않은 변경이 있으면 **`임시 저장하지 않은 내용이 있어요` 다이얼로그**를 띄운다. 왼쪽이 `닫기`(텍스트 버튼·머무름), 오른쪽이 `나가기`(`backgroundDangerSubtle`·`textDanger`·저장하지 않고 이탈) | 사용자 결정. 자동 저장이 사라진 만큼 소실 가능성이 실재하므로 이탈 직전에 알린다 |
| D11 | 임시 저장은 **쓰기 중 추가 요청을 버리고**, 마지막으로 써 넣은 스냅숏과 같으면 쓰기를 건너뛴 채 확인 표시만 다시 보여 준다. 판정 장부(`persistedSnapshot`·`draftPersisted`)는 UiState 가 아니라 ViewModel·스토어가 직접 들고 있다 | 연타로 눌러도 디스크는 한 번만 건드리면서 버튼이 죽은 것처럼 보이지 않는다. UiState 반영은 이벤트 채널을 거쳐 한 박자 늦어 "이미 저장됨" 판정 기준으로 쓸 수 없다(평가 동기화 장부와 같은 이유) |
| D13 | 버튼 색은 상태별로 직접 정하고 잠금 여부와 무관하게 같은 값을 넘긴다 | `enabled` 에 색까지 맡기면 저장 완료로 잠긴 버튼이 "누를 수 없음" 회색으로 보인다. 잠금은 클릭만 막는다 |
| D12 | 임시 저장 버튼의 체크 아이콘과 스피너는 `sizes.icon-small`(16dp)을 쓴다. 이 토큰을 새로 두고 기존에 raw `16.dp` 로 적혀 있던 "키워드 추가" 버튼 아이콘도 옮긴다 | 40dp 컨트롤 안에서 20dp 아이콘은 라벨보다 커 보인다. 같은 값을 두 곳이 각자 적어 두면 다음 변경에서 갈라진다 |
| D10 | 퍼널의 경고 다이얼로그 셋(미저장 이탈·소실·다시 선택하기)은 한 컴포저블을 공유하고, 버리는 동작을 오른쪽 위험 버튼에·되돌아가는 동작을 왼쪽 텍스트 버튼에 고정한다 | 사용자 결정. 경고마다 버튼 자리와 색이 다르면 어느 쪽이 무엇을 버리는지 매번 다시 읽어야 한다. 기존 "다시 선택하기" 경고가 이미 쓰던 배치를 정본으로 삼는다 |
| D7 | 이탈은 저장하지 않은 변경을 **저장하지 않는다**. 마지막으로 저장된 스냅숏이 그대로 재개 지점이 된다 | D6에서 사용자가 버리기를 선택한 것을 다시 저장하면 경고가 거짓말이 된다. 진행 중 요청 레코드는 서버에서 돌고 있는 복구 대상이라 그대로 유지한다 |
| D8 | 활성 스토리라인 탭(`progress.activeStorylineIndex`)은 저장하지 않은 "내용"으로 세지 않는다. 저장할 때는 함께 나간다 | 탭을 훑어보기만 해도 이탈 경고가 뜨면 경고가 신호를 잃는다. 키워드 단계의 활성 카테고리를 저장하지 않는 기존 결정(E12b)과 같은 성격이다 |
| D9 | 보존할 것도 저장할 것도 없는 이탈은 기존 소실 경고(`스토리를 그만 만들까요?`) 문구를 그대로 쓴다. 두 경고는 사라지는 대상이 달라 문구를 합치지 않는다 | 생성이 확정적으로 실패해 레코드까지 지워진 경우는 "저장하지 않은 변경"이 아니라 애초에 재개할 재료가 없는 상태다 |

## 구현 단계

1. `feature:create` — `DraftSave.kt`(`DraftSaveStatus`·`DraftSaveUiState`·`FunnelExitWarning`·표시 유지 시간 상수).
2. `feature:create` — `CreateFunnelChrome`의 뱃지를 `DraftSaveButton`으로 교체, 소실·미저장 경고를 `FunnelExitWarningDialog` 하나로 합침, `SaveDraftWhenBackgrounded`(Activity `ON_STOP`) 추가.
3. `feature:create` — 생성 스토어의 디바운스 제거, `draftSave` 상태와 `saveDraft()`·`savedProgress` 기준선 도입, `leaveFunnel()`이 저장하지 않도록 변경.
4. `feature:create` — 키워드 VM의 디바운스 수집 제거, `savedSnapshot` 기준선과 저장·경고 인텐트 추가. 스토리라인·추가 정보 VM에 같은 인텐트 배선.
5. `core:ui` — 임시 저장 버튼·미저장 경고 문자열.
6. 단위 테스트와 정적 검사.

## 검증

- 태그: `state-restore`(저장 시점이 바뀌어 재개 재료가 달라짐), `race-condition`(요청 단계 쓰기와 사용자 저장의 우선순위)
- 단위 테스트: 변경 전 버튼 잠김·변경 후 풀림·저장 후 다시 잠김, 입력만으로는 쓰지 않음, 버튼 저장 후 레코드·`hasUnsavedChanges`, 2초 뒤 표시 복귀, 저장 뒤 재편집 시 표시 회수, 입력 전부 삭제 후 저장이 레코드를 지움, 진행 중 레코드는 덮지 않음, 미저장 이탈 경고와 `나가기`가 저장하지 않음, 탭만 옮긴 이탈은 경고 없음.
- 수동 검증: 각 단계에서 편집 후 홈 버튼으로 백그라운드 → 복귀 → 이탈 → 배너 재개 지점 확인. 저장 중·저장 완료 표시 중 버튼 잠금과 스피너, 2초 뒤 라벨 복귀.
