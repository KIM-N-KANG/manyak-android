# 메인 탭 셸 (KNK-970)

> **KNK-1197 구조 이전 안내 (2026-09-05)** — 아래 모듈 경로·코드 예시·검증 명령은 작성 당시 기록입니다. 현재 소유 위치와 검증 결과는 [모듈 재구성 기록](./module-reorganization.md), 현재 계층·의존 규칙은 [하네스 모듈 아키텍처](../../../knk-harness/docs/planning/android-module-architecture.md)를 따릅니다.

- 계약 정본: 하네스 `3-3-android-app.md` §3-3-3 메인 탭 셸 (KNK-969로 확정)
- 작성일: 2026-08-23

## 목표

메인 그래프에 홈·채팅·마이 세 탭을 두르는 chrome(상단 헤더 + 하단 내비게이션)을 만들고 세 목적지를 오갈 수 있게 합니다. 탭 화면의 콘텐츠는 후속 작업(KNK-866·KNK-869·KNK-778)이 채웁니다.

## 제외 범위

- 스토리 목록·채팅 목록의 데이터 연동
- 생성 FAB와 제작 퍼널 진입
- 마이 화면의 초대·연동·서비스 안내 확장
- 관측 이벤트 발화

## 이번에 새로 내린 결정

### 1. 셸은 바깥 백스택의 키 하나로 두고, 탭별 백스택은 셸이 소유한다

메인 백스택에는 `MainTabsRoute`(셸)와 전체 화면 목적지들이 나란히 쌓이고, 세 탭은 셸이 들고 있는 탭별 백스택 안에만 존재합니다.

| 대안 | 채택 안 한 이유 |
| --- | --- |
| 백스택 하나에 전부 두고 목적지에 따라 chrome을 조건부로 그림 | 바깥 `Scaffold`가 전체 화면 목적지에도 콘텐츠 여백을 물려, 자체 `Scaffold`를 가진 법적 문서 화면에서 인셋이 두 번 적용됩니다. 조건 분기가 목적지마다 늘어납니다 |
| 탭 셋을 한 백스택에 두고 전환할 때마다 교체 | 백스택에서 빠진 탭의 상태가 함께 사라져 하네스 §3-3-3의 상태 유지 `MUST`를 지킬 수 없습니다 |
| 탭마다 `Scaffold`를 두고 chrome을 화면이 그림 | 하네스 §3-3-3이 금지합니다(헤더 소유는 셸) |

**영향** — 백스택이 넷(바깥 하나 + 탭 셋)이 됩니다. 탭 화면에서 전체 화면 목적지로 갈 때는 바깥 백스택에 쌓아야 하므로, 화면에 `onNavigateTo*` 콜백을 내려 셸이 바깥 백스택에 연결합니다. 화면이 이동 객체를 받지 않는 기존 규칙은 그대로입니다.

**뒤로가기** — 홈이 아닌 탭에서는 홈의 시작 목적지를 그 탭 백스택 밑에 깔아 그립니다. 되감을 것이 있으면 탭 안에서 되감고 없으면 홈으로 떨어지며, 홈 탭에서는 밑에 아무것도 없어 앱을 벗어납니다. 조건 분기가 아니라 그리는 목록의 구성이 규칙을 담습니다.

### 2. 탭 아이콘 크기 24dp를 `ManyakSizes`에 새 토큰으로 추가한다

기존 `{sizes.icon}`(20dp)은 "라벨 옆에 붙는 아이콘"의 크기라, 라벨 위에 놓여 탭의 주된 시각 요소가 되는 탭 아이콘에는 작습니다. 웹 하단 네비게이션도 24px입니다. 컨트롤 크기는 토큰 정본이 아니라 이 레포가 소유하므로(`DESIGN.md`) 여기서 단계를 추가하고 `DESIGN.md`를 함께 갱신합니다.

### 3. 로고 렌더를 `:core:ui`의 공용 컴포저블로 올린다

로그인 화면에 이어 헤더가 두 번째 사용처입니다. 원본 비율(89:32) 상수가 두 곳에 복제되는 것을 막습니다(`DESIGN.md` 갱신 지침 6).

### 4. 셸의 두 컴포넌트는 M3 위에 색만 얹는다

헤더는 `TopAppBar`, 하단 바는 `NavigationBar`를 그대로 씁니다. 인셋·높이·최소 터치 타깃·시맨틱을 직접 계산하지 않기 위해서입니다. 이 디자인 시스템에 없는 요소만 골라 지웁니다.

| | 지우는 것 | 방법 |
| --- | --- | --- |
| `TopAppBar` | 없음 | 색과 제목 슬롯만 지정 |
| `NavigationBar` | 알약 모양 선택 표시자 | `indicatorColor = Color.Transparent` |
| `NavigationBar` | 눌림 피드백 | `CompositionLocalProvider(LocalRippleConfiguration provides null)` |

`NavigationBarItem`은 표시자 자리에 리플을 그리고 그 배치는 공개 API로 바꿀 수 없습니다. 그래서 리플을 컴포넌트 밖에서 끕니다. `LocalRippleConfiguration`은 실험 API가 아니고, "`null`을 주면 리플을 끈다"가 문서화된 용법입니다. 반대로 `TopAppBar`는 아직 실험 API라 `@OptIn`이 필요하며, 사용처를 `ManyakSectionHeader` 하나로 묶어 시그니처가 바뀌어도 고칠 곳이 한 곳이게 했습니다.

> 중간에 하단 바를 `Surface` + `Row` + `selectable`로 직접 만든 적이 있습니다. 리플을 라벨까지 덮으려면 그 방법뿐이었기 때문인데, 리플 자체를 없애기로 하면서 직접 만들 이유가 사라졌습니다.

### 5. 빈 탭 화면은 콘텐츠 없이 여백만 적용한다

플레이스홀더 문구를 넣지 않습니다. 다음 작업이 바로 지울 문자열 리소스가 남기 때문입니다.

### 6. feature 모듈을 화면 단위로 바꾼다

셸을 만들며 홈 탭이 `:feature:story` 안에 들어가자 모듈 이름과 화면 이름이 어긋났습니다. 모듈을 화면 단위로 바꿔 `:feature:home`·`:feature:chat`·`:feature:my`가 각각 탭 하나를 맡고, 화면은 모듈 루트 패키지에 둡니다. 하네스 §3-3-2의 도메인 단위 규칙을 이 결정으로 대체했고, 늘어나는 모듈 수와 `:core:*` 경유 비용은 그 결정 기록에 적었습니다.

## 외부 합의가 필요한 항목

없습니다. 세 탭의 순서·이름·아이콘 의미는 공통 계약([`3-2-web-app.md`](../../../knk-harness/docs/product-specs/3-2-web-app.md) §3-2-3)에 이미 있고, outline·filled 쌍은 하네스 §3-3-3에서 플랫폼 차이로 확정했습니다.

## 구현 단계

1 → 2 → 3 순서이고, 1 안의 세 갈래는 서로 막지 않습니다.

### 1. 자산과 공용 컴포넌트 (`:core:ui`)

- 1a. 탭 아이콘 벡터 6종 추가 — `ic_nav_{home,chat,my}_{outline,filled}.xml`. 색은 사용처에서 tint하므로 자산 자체는 단색으로 둡니다.
- 1b. `ManyakSizes.tabIcon` 추가, `DESIGN.md`의 크기·컴포넌트 절 갱신.
- 1c. 문자열 `main_tab_home`·`main_tab_chat`·`main_tab_my` 추가, 쓰이지 않게 되는 `my_title` 삭제.
- 1d. `ManyakLogo`·`ManyakSectionHeader`·`ManyakNavigationBar` 작성. 셋 다 라우트를 모르고 값과 콜백만 받습니다.

**완료 조건** — `:core:ui`가 단독으로 컴파일되고, 로그인 화면이 `ManyakLogo`를 쓰도록 바뀐 뒤에도 로고 크기가 그대로입니다.

### 2. 라우트와 탭 화면

- 2a. `:core:navigation`에 `MainTabsRoute`·`HomeRoute`·`ChatListRoute` 등록.
- 2b. `:feature:home` 모듈 신설 — `HomeScreen.kt`.
- 2c. `:feature:chat` 모듈 신설 — `ChatListScreen.kt`.
- 2d. `MyScreen`이 자체 제목을 버리고 `contentPadding`을 받도록 변경.

**완료 조건** — 세 화면 모두 `contentPadding: PaddingValues`를 받고 자기 헤더를 그리지 않습니다.

### 3. 셸 배선 (`:app`)

- 3a. `MainTab` 열거형 — 목적지와 아이콘·이름을 맺는 유일한 자리.
- 3b. `MainTabsScreen` — `Scaffold` + 탭별 백스택. 탭 전환은 어느 백스택을 그릴지 고르는 일이라 이력에 쌓이지 않고, 떠난 탭의 상태는 그 백스택과 함께 남습니다.
- 3c. `MainNavDisplay`가 `MainTabsRoute`로 시작하고 법적 문서를 그 위에 쌓습니다.

**완료 조건** — 로그인 후 세 탭을 오갈 수 있고, 마이 탭에서 뒤로가기가 홈으로 한 번에 돌아오며, 홈에서 한 번 더 누르면 앱을 벗어납니다.

빌드 전체를 매 단계 돌리지 않고, 1·2단계는 바뀐 모듈의 컴파일만 확인합니다.

**셸 검수 1·2·3은 자동화하지 않았습니다.** Compose UI 테스트로 쓸 수는 있지만 계측 테스트라 기기가 필요하고, 현재 CI는 `check`와 `assembleDebug`만 돌립니다. `MainTabsScreen` 이 Hilt ViewModel 을 쓰는 마이 화면을 품고 있어 테스트 하네스도 함께 세워야 합니다. 계측 테스트를 CI에 붙이는 것을 선행 과제로 남기고(하네스 §3-3-7 `결정 필요`), 그때 이 셋을 함께 자동화합니다.
