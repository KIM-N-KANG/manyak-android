# 빌드·배포·운영

## 경계

하네스의 배포 스펙, `docs/plans/_project.md`, 실제 Gradle·CI 구성을 먼저 읽습니다. 배포·원격 설정·스토어 변경 같은 외부 작업은 사용자가 명시적으로 요청한 범위에서만 수행합니다.

## 환경과 비밀

- 환경과 debug/release 빌드 방식을 별도 축으로 관리합니다.
- API, 인증, 푸시, 관측 설정의 환경별 주입 지점을 한 곳으로 모읍니다.
- 필수 설정이 없으면 운영 빌드가 안전하지 않은 기본값으로 넘어가지 않게 합니다.
- 앱 번들에 서버 비밀을 넣지 않고 서명키의 보관·백업·접근 권한을 정합니다.

## CI

- PR에는 빠르고 안정적인 정적 검사·단위 테스트·debug 패키징을 둡니다.
- 계측 테스트와 release 빌드는 변경 위험과 실행 시간을 보고 병합 후 또는 릴리스 단계에 둡니다.
- 같은 전체 작업을 로컬과 PR CI에서 기본으로 중복 실행하지 않습니다.
- 축소를 사용하는 release variant는 실제로 빌드하고 크래시 복원 정보를 함께 보존합니다.

## 호환성과 대응

- 서버는 지원 중인 구버전 앱의 요청 계약을 유지합니다.
- 위험한 API 변경은 새 계약과 유지 기간을 정합니다.
- 단계적 배포의 관찰 지표와 중단 기준을 배포 전에 정합니다.
- 기능 플래그·긴급 차단은 사고 비용이 큰 기능에만 둡니다. 모든 기능에 플래그를 만들지 않습니다.
- 강제 업데이트는 이미 배포된 클라이언트가 이해할 수 있는 계약이 있을 때만 사용합니다.

## 릴리스 점검

실제 출시 준비에서만 다음을 확인합니다.

- 운영 빌드의 서버·인증·푸시·관측 대상
- 개발용 기능과 민감 로그 비활성화
- release 빌드와 필요한 축소 동작
- 구버전 서버 호환성
- 버전 코드, 단계적 배포, 중단 기준
- 긴급 차단·설정 조회 실패의 안전한 기본 동작

점검 실행은 `release` 위험 태그로 `android-change-verification`에 맡깁니다. 프로젝트 공통 결정이 바뀔 때만 `_project.md`를 갱신합니다.
