# 기능 개발 계획

## 목적

구현 전에 확정해야 하는 결정만 골라 의존 순서가 있는 계획으로 만듭니다. 계획의 크기는 호출된 스킬 수가 아니라 변경을 되돌리는 비용으로 판단합니다.

## 계획이 필요한 경우

다음 중 하나면 계획을 만듭니다.

- 사용자가 계획이나 설계를 요청했습니다.
- 새 API 계약, 사용자 데이터 저장소와 마이그레이션, 인증, 개인정보, 권한 정책이 생깁니다.
- 새 모듈 경계, 백그라운드 작업, 알림과 딥링크, 배포 정책을 정해야 합니다.
- 여러 영역의 순서가 얽혀 뒤 단계가 앞 단계를 뒤집을 수 있습니다.

기존 프로젝트 결정을 그대로 따르는 국소 변경과 재생성 가능한 캐시의 채움 규칙이 확정된 단순 additive 스키마 변경은 짧은 구현 순서만 제시합니다. 스킬 개수로 기능 분할 여부를 판단하지 않습니다.

## 작업 흐름

1. 하네스의 관련 제품 문서, `AGENTS.md`, 변경이 닿는 코드를 읽습니다.
2. 이미 확정된 결정과 이번에 새로 정해야 할 결정을 나눕니다.
3. 현재 환경이 제공하는 스킬 목록의 설명으로 필요한 스킬만 고릅니다. 모든 `SKILL.md`를 훑지 않습니다.
4. 선택한 스킬에서는 이번 결정에 필요한 항목만 적용합니다. 기존 결정 준수 여부만 확인하면 되는 스킬은 호출하지 않습니다.
5. 결정, 외부 합의가 필요한 항목, 구현 순서를 합칩니다. 막히지 않는 단계는 병렬로 표시합니다.
6. 검증은 실행하지 않고 확인할 위험과 시점만 적습니다. 실제 검증은 AGENTS.md "검증" 절과 PR 전 리뷰(pr-review, ui-review)를 따릅니다.
7. 아래 "검토"가 필요한 계획이면 사용자에게 내놓기 전에 한 번 검토합니다.
8. 여러 기능이 따라야 하는 공통 기술 결정이 실제로 바뀌면 이유를 하네스 결정 기록에 남깁니다. 이 저장소가 소유하는 빌드와 주입 값이 바뀌면 `AGENTS.md`를 갱신합니다.

## 계획 기록

저장소에 계획 파일을 만들지 않습니다. 계획은 대화로 제시하고, 구현을 마치면 확정된 결정과 실행 결과를 PR 본문에 옮깁니다. 되돌리기 비싼 선택의 이유는 하네스 결정 기록에 둡니다.

계획과 PR 본문에는 다음만 남깁니다.

- 기능 목표와 제외 범위
- 이번 기능에서 새로 내린 결정과 근거
- 서버, 제품, 디자인 합의가 필요한 항목과 막는 단계
- 의존 순서가 있는 구현 단계와 확인 가능한 완료 조건
- 확인할 위험과 검증 시점

일반론, 기존 프로젝트 결정의 복사본, 전체 스킬 체크리스트는 넣지 않습니다.

## 검토

사용자가 계획 리뷰를 요청했거나, 계획에 새 계약, 사용자 소유 데이터의 비가역적 변경, 인증, 권한, 배포 결정이 있을 때만 합니다. 작은 변경이나 재생성 가능한 캐시 계획에는 하지 않습니다.

계획을 구현했을 때 재작업을 만드는 가정과 누락만 찾습니다. 문장 형식이나 일반적인 모범 사례는 지적하지 않습니다. 계획이 참조하는 코드와 프로젝트 결정만 필요한 만큼 확인합니다.

다섯 방향으로 공격합니다.

1. **범위와 근거**: 결정이 실제 요구와 코드에 근거하며 불필요한 확장을 만들지 않는가
2. **계약과 실패**: 서버, 저장소, 인증, 외부 입력 실패가 즉석 결정으로 남지 않았는가
3. **순서와 가역성**: 숨은 의존 때문에 뒤 단계가 앞 단계를 버리게 하지 않는가
4. **완료와 검증**: 완료 조건이 관찰 가능하고 검증 비용이 위험에 비례하는가
5. **미결정**: 지금 정할 수 있는 일을 미뤘거나 외부 합의가 필요한 값을 임의로 확정하지 않았는가

| 등급 | 기준 |
| --- | --- |
| 재설계 | 구현하면 구조, 계약, 데이터를 버리고 다시 만들어야 합니다 |
| 보완 | 현재 구조를 유지한 채 계획에 빠진 내용을 추가할 수 있습니다 |
| 확인 | 구현 중 확인해도 재작업 가능성이 낮습니다 |

각 발견에는 상황, 예상 결과, 고칠 계획 위치를 적고 가장 큰 위험 하나를 고릅니다. 발견이 없으면 공격한 범위와 확인하지 못한 근거를 밝힙니다. 리뷰만 요청받았다면 계획이나 코드를 직접 고치지 않고, 계획 작성이나 구현 중에 검토했다면 발견을 원래 범위 안에서 반영합니다.

## 실행 경계

- 계획만 요청받았다면 코드를 바꾸지 않습니다.
- 구현까지 요청받았다면 계획 완료 후 다시 승인을 묻지 않고 구현을 계속합니다. 범위를 넓히는 변경만 사용자에게 확인합니다.
- 계획을 바꾸는 데 꼭 필요한 정보만 질문하고, 나머지는 근거가 있는 기본값으로 진행합니다.
