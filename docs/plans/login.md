# 로그인·계정 관리 (KNK-865)

- 작성일: 2026-08-22
- 정본: 하네스 [`3-3-android-app.md`](../../../knk-harness/docs/product-specs/3-3-android-app.md) §3-3-1·§3-3-2·§3-3-3·§3-3-4·§3-3-7. 아래는 그 결정을 **이 레포에서 실행하는 순서**와 **이번에 새로 내린 결정**만 담습니다.

## 목표

앱 시작 → (미로그인) 약관·개인정보처리방침 열람 → 구글·카카오 실제 로그인 → 회원 마이 → 로그아웃까지 **하나의 세로 흐름**을 닫습니다. 스펙의 모듈 도입 1단계(`:core:domain` · `:core:data` · `:core:ui` · `:core:navigation` · `:feature:login` · `:feature:legal` · `:feature:my`)를 이 흐름으로 채웁니다.

## 제외 범위

- 홈·채팅·스토리 등 메인 제품 화면(마이 진입용 최소 골격만 둡니다)
- 계정 연동(`/auth/links/*`) — 재인증 토큰 신선도 수단이 스펙에서 `결정 필요`
- Amplitude·Crashlytics 배선(스펙 2단계)
- 신규 가입 초대 코드 안내 다이얼로그(`isNewUser` 응답 필드는 받아 두되 화면은 다음 범위)

## 이번에 새로 내린 결정

| # | 결정 | 근거 |
| --- | --- | --- |
| 1 | **법적 문서는 앱 내 WebView로 웹 페이지를 연다.** `{BASE_WEB_URL}/terms`·`/privacy`를 전용 목적지에서 로드한다 | 본문 정본이 웹 레포의 `legal/content/*.ts` 하나뿐이라, 복제하면 시행일·버전이 갈라진다. WebView는 구조적으로 불일치를 만들지 않고 개정 시 앱 배포가 필요 없다. 대가는 오프라인 미열람과 웹 레이아웃 노출이며 수용한다 |
| 2 | **제공자 키는 `local.properties`에서 주입한다.** 구글 서버 클라이언트 ID는 `BuildConfig`, 카카오 네이티브 앱 키는 `BuildConfig` + 매니페스트 placeholder로 내린다 | 값은 APK에 실려 비밀은 아니지만 소스에 하드코딩하면 빌드 타입별 주입(§3-3-4 `MUST`)이 깨진다. `BASE_URL`이 이미 같은 방식이라 패턴을 맞춘다 |
| 3 | **키가 비면 로그인 시작 단계에서 명시적으로 실패시킨다.** 빈 값으로 SDK를 호출하지 않는다 | 빈 클라이언트 ID는 제공자 오류로 흩어져 원인 파악이 어렵다. `device_id` 빈 값 금지(§3-3-4)와 같은 이유 |
| 4 | **로그인 화면 문구는 웹 카피를 그대로 옮긴다** | 문구 정본은 3-1(FE-SCREEN-008)이며 앱이 새로 쓰지 않는다 |
| 5 | **`allowBackup="false"`로 바꾸고 토큰 파일을 백업·기기 이전 규칙에서도 제외한다** | §3-3-4 이중 방어. 기준 매니페스트가 `true`라 이번 변경에 포함된다 |

## 외부 합의가 필요한 항목

| 항목 | 막는 단계 |
| --- | --- |
| dev 서버 허용 목록에 구글 **웹 클라이언트 ID + Android 클라이언트 ID**, 카카오 **네이티브 앱 키**가 들어 있는지 확인(`MANYAK_KAKAO_CLIENT_IDS`) | 실기기 로그인 성공 검증(검수 #1) |
| 운영 빌드용 클라이언트 ID·네이티브 앱 키, 스토어 앱 서명 키 지문 등록 | 검수 #10(스토어 배포본 로그인) |
| 웹 도메인 확정(`manyak.app`) 및 법적 문서 경로 | 법적 문서 화면(단계 6) |

## 구현 단계

각 단계는 컴파일·정적 검사를 통과한 상태로 커밋합니다. 괄호 안은 병렬 가능 여부입니다.

| 단계 | 내용 | 완료 조건 |
| --- | --- | --- |
| 0 | 의존성(Version Catalog)·키 주입·매니페스트 배선. DataStore, Credential Manager + Sign in with Google, Kakao SDK v2, `androidx.security`(Keystore 래핑은 직접), WebView 목적지용 의존성 | `assembleDebug` 통과, `BuildConfig`에 두 키가 뜬다 |
| 1 | 모듈 6개 생성과 의존 방향 배선. `:core:domain`·`:core:common`은 `kotlin-jvm` | 각 모듈 컴파일, 의존 방향 테스트 통과 |
| 2 | `:core:ui` — `MviViewModel<I,S,E,F>` 베이스, 문자열 리소스 전량, 기존 `ui/theme` 이동 | 베이스 클래스 계약 테스트(직렬화·overflow·replay 없음) 통과 |
| 3 | `:core:domain` — 세션 상태·사용자 모델·오류 타입·Repository 인터페이스 | 순수 Kotlin 컴파일(안드로이드 참조 시 컴파일 에러) |
| 4 | `:core:data` (A) `device_id` 저장소 (B) Keystore 암호화 토큰 저장소 + 시계 앵커·부팅 세대 원자 저장 (C) Retrofit API·오류 변환 (D) 인터셉터: 기기 헤더 · 선제 재발급 단일 비행 · 401 1회 반응형 (E) 프로필 캐시 (F) 제공자 어댑터(Google·Kakao, SDK 인증과 서버 호출 분리) | 검수 #3·#4·#5·#11 단위 테스트 통과 |
| 5 | `:app` — `SessionTerminationCoordinator`와 종료 정리 저널, DI 조합, 루트가 세션 상태로 그래프 선택 | 검수 #7의 자동 검증 가능 부분 통과 |
| 6 | `:core:navigation` 라우트 등록 · `:feature:legal`(WebView) · `:feature:login` · `:feature:my`(로그아웃 버튼) | 세로 흐름이 에뮬레이터에서 동작 |
| 7 | 실기기 검증과 문서 갱신 | 아래 검증 표 |

## 검증

| 위험 태그 | 확인 | 시점 |
| --- | --- | --- |
| 자동(CI) | 검수 #3·#4·#5·#11, #7의 경쟁·재시작 주입, `MviViewModel` 계약 | 단계 4·5 완료 시 |
| 자동(CI) | `./gradlew check`, `./gradlew assembleDebug` | 매 단계 |
| 수동(실기기) | 검수 #1 — 법적 문서 왕복·구글 로그인·재실행 복원·로그아웃까지 에뮬레이터에서 확인. **카카오 로그인만 남음** | 단계 6 완료 후 |
| 수동(실기기) | 검수 #2 — `device_id` 가 없으면 인터셉터가 요청을 막으므로 로그인 200 은 헤더가 실렸다는 간접 증거다. 서버 로그로 직접 확인 필요 | 서버 확인 시 |
| 수동(배포본) | 검수 #10 | 스토어 배포 준비 시 |
| 이번 범위 밖 | 검수 #8·#9(계정 연동) | 연동 기능 구현 시 |

`android-change-verification`에 넘길 위험은 **인증·사용자 귀속 저장소·외부 SDK**입니다. 전체 기기 매트릭스는 릴리스에서 수행합니다.
