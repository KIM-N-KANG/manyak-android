# 적응형 UI와 접근성

## 범위 선택

`docs/plans/_project.md`와 제품 스펙에서 지원 창 크기, 방향, 언어, 접근성 기준을 먼저 확인합니다. 이번 변경이 실제로 건드리는 축만 검토합니다.

## 핵심 기준

### 창과 시스템 영역

- 기기 종류가 아니라 현재 사용 가능한 폭과 높이로 레이아웃을 판단합니다.
- 레이아웃 분기는 정보 구조가 실제로 달라질 때만 추가합니다.
- 시스템 바와 키보드 인셋은 배경과 콘텐츠에 필요한 위치에서 각각 처리합니다.
- 창 크기가 바뀌어도 사용자가 입력한 값과 현재 위치가 불필요하게 초기화되지 않게 합니다.

### 글자와 지역화

- 텍스트를 고정 높이에 가두지 않고 핵심 내용의 잘림 정책을 명시합니다.
- 사용자에게 보이는 문자열과 날짜·숫자 형식은 리소스와 지역 형식 기능을 사용합니다.
- 문장을 조각내지 않고 번역문 길이가 늘어날 수 있게 배치합니다.
- 지원 언어에 RTL이 있으면 시작·끝 기준과 방향성 아이콘을 확인합니다.

### 접근성

- 조작 요소에는 의미와 상태를 제공하고 장식은 낭독에서 제외합니다.
- 낭독·키보드 포커스 순서가 시각 순서와 일치하게 합니다.
- 색만으로 상태를 전달하지 않고 밝은·어두운 테마에서 대비를 유지합니다.
- 자동 소멸 안내와 시간 제한 조작에는 다시 확인하거나 연장할 경로를 둡니다.

## 결과와 검증

지원 정책 변경, 화면별 레이아웃 결정, 발견된 위반만 보고합니다. 이 스킬에서 기기 매트릭스를 직접 실행하지 않습니다.

변경된 화면에 실제 확인이 필요하면 `adaptive-ui` 위험 태그와 해당 축만 `android-change-verification`에 전달합니다. 전체 언어·기기·접근성 매트릭스는 릴리스 또는 명시적 QA 요청에서 수행합니다.
