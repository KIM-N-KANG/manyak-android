# Compose 구현

## 목적

Compose 화면을 실제로 만들고 확인하는 작업 스킬입니다. 화면을 만들 때마다 반복되는 점검을 대신합니다.

**무엇을 지원할지는 여기서 정하지 않습니다.** 어떤 창 크기를 지원하고, 폰트를 어디까지 키우고, 어떤 언어를 넣고, 접근성을 어느 수준으로 보장할지는 고려 사항 6번 항목 스킬에서 정합니다. 상태를 어디에 둘지는 고려 사항 2번 항목 스킬, 화면을 어느 모듈에 두고 어떻게 이동할지는 고려 사항 1번 항목 스킬입니다. 이 스킬은 **그 결정들을 Compose 코드로 옮기고 실제로 그렇게 보이는지 확인**합니다.

## 선행 전제: 컴포저블은 언제 다시 실행될지 모릅니다

리컴포지션은 프레임마다 일어날 수 있고 순서도 보장되지 않습니다. 여기서 두 규칙이 나옵니다.

- **컴포저블 본문에 부수 효과를 두지 않습니다.** 네트워크 호출, 로그, 상태 변경을 본문에서 직접 하면 몇 번 실행될지 알 수 없습니다. 효과는 전용 자리에 두고 키를 명시합니다.
- **컴포저블은 인자만 보고 그려야 합니다.** 밖에서 못 보는 상태를 안에 숨기면 Preview와 테스트에서 그 화면을 재현할 수 없습니다.

## 적용 범위 판단

| 요청 | 하는 일 |
| --- | --- |
| 새 화면 구현 | 재사용 탐색 → 구조 → 효과·키 점검 → Preview → 컴파일 확인 |
| 기존 화면에 요소 추가 | 재사용 탐색, 해당 부분의 효과·키, Preview 갱신 |
| 리컴포지션·깜빡임 문제 | 효과의 키와 수명, 상태 위치 |
| 목록이 튀거나 상태가 섞임 | 항목 키 |
| Preview·스크린샷 정비 | Preview 매트릭스 |

## 먼저 찾습니다

**만들기 전에 이미 있는지 봅니다.** 프로젝트의 테마, 색·타이포 정의, 공통 컴포넌트를 읽고 재사용합니다. 같은 버튼이 화면마다 다시 만들어지면 디자인이 갈리고, 나중에 한 번에 바꿀 수 없습니다.

- 있으면 씁니다. 모자라면 **기존 것을 확장할지 새로 만들지 사용자에게 묻습니다.** 조용히 새로 만들지 않습니다.
- 색과 치수를 화면에서 직접 쓰지 않고 테마를 통합니다. 직접 쓴 값은 다크 모드에서 드러납니다.

## 구조

- **상태를 끌어올립니다.** 컴포저블은 값과 콜백을 받고, 상태는 위에서 관리합니다. 그래야 Preview와 테스트가 가능합니다.
- **화면 컴포저블에 이동 객체를 넘기지 않습니다.** 사건을 콜백으로 올리고 이동은 조립 지점에서 다룹니다. 이 원칙은 고려 사항 1번 항목 스킬에서 정한 것과 같습니다.
- **흐름을 생명주기에 맞춰 수집합니다.** 화면이 보이지 않는 동안에도 수집이 살아 있으면 배터리를 쓰고, 돌아왔을 때 밀린 값이 한꺼번에 들어옵니다.

## 반복 점검

| 점검 | 놓쳤을 때 |
| --- | --- |
| 부수 효과의 키가 맞는가 | 키가 너무 좁으면 다시 실행되지 않고, 너무 넓으면 리컴포지션마다 다시 실행됩니다 |
| 효과가 취소를 다루는가 | 화면을 떠나도 작업이 남아 사라진 화면의 상태를 건드립니다 |
| 목록 항목에 안정된 키가 있는가 | 항목이 추가·삭제될 때 선택 상태와 애니메이션이 엉뚱한 항목에 붙습니다 |
| 터치 대상이 충분한가 | 작은 아이콘은 눌리지 않습니다. 기준은 고려 사항 6번 항목 스킬에 있습니다 |
| 화면 요소에 접근성 정보가 있는가 | 아이콘만 있는 버튼은 읽어 줄 것이 없습니다 |

## Preview

**한 화면에 하나만 만들지 않습니다.** 기본, 다크 모드, 큰 폰트, 좁은 창과 넓은 창을 각각 만듭니다. 지원 범위는 고려 사항 6번 항목 스킬의 결정을 따릅니다.

빈 상태, 로딩, 오류 상태의 Preview도 만듭니다. 정상 데이터만 있으면 나머지 상태는 아무도 보지 못한 채 배포됩니다. 이 상태 구분은 고려 사항 7번 항목 스킬에서 정합니다.

## 작업 흐름

1. **기존 테마와 공통 컴포넌트를 읽습니다.** 재사용할 것과 새로 만들 것을 나눕니다.
2. **화면이 받을 값과 올릴 사건을 먼저 정합니다.** 이것이 컴포저블의 인자입니다.
3. **구현합니다.** 상태는 위로, 효과는 전용 자리에 키와 함께 둡니다.
4. **위 반복 점검을 하나씩 확인합니다.**
5. **Preview를 만듭니다.** 테마·폰트 배율·창 크기와 화면 상태를 조합합니다.
6. **컴파일해 확인합니다.** 실행할 명령 선택은 `android-change-verification` 스킬을 씁니다.
7. **필요하면 UI 테스트를 씁니다.** 테스트를 먼저 쓸 경우 `android-tdd` 스킬을 씁니다.
8. **컴파일과 확인이 통과한 뒤에만 완료로 보고합니다.** 코드를 썼다는 것과 동작한다는 것은 다릅니다.
