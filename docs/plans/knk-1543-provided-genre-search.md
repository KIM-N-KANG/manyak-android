# KNK-1543 제공 장르 검색

## 범위와 정본

간편 제작 장르의 직접 입력 버튼을 검색 가능한 콤보박스로 교체합니다. 사용자 제공 검색과 확장 SVG를 기능 모듈 vector drawable로 변환하며 기존 입력 표면을 사용합니다. 일반 제작과 수정 화면의 연결은 해당 화면을 구현하는 후속 작업에 남습니다.

- 사용자 계약: [Android spec 제작과 데이터 보존](../../../knk-harness/docs/spec/3-3-android-spec.md#3-3-3-제작과-데이터-보존)
- 현재 구조: [Android design 제작과 상태 복원](../../../knk-harness/docs/design/1-2-android-design.md#1-2-7-제작과-상태-복원)
- 결정: [A-057 검색과 초안 호환](../../../knk-harness/docs/adr/1-3-android-adr.md#a-057-제공-장르-검색과-이전-초안-호환), [A-058 선택 토글과 칩 순서](../../../knk-harness/docs/adr/1-3-android-adr.md#a-058-장르-검색-선택-토글과-대표-칩-순서-유지)
- API 근거: 2026-10-05 dev Swagger의 `GET /api/v1/stories/genres`, 실제 응답 전체 197개와 대표 15개 확인. 검색어 원문 상한 30자.
- 검색 캐시와 로딩 표시 결정: [A-059](../../../knk-harness/docs/adr/1-3-android-adr.md#a-059-장르-검색-캐시와-지연-로딩-표시), [A-060 200ms 기준](../../../knk-harness/docs/adr/1-3-android-adr.md#a-060-장르-검색-로딩-표시-기준-조정)

## 구현 순서와 결과

1. `GenreCatalog`와 Repository 조회를 추가했습니다. 빈 검색어와 입력 검색 모두 서버 결과를 사용합니다.
2. 키워드 ViewModel 수명의 `GenreSearch`에서 250ms 대기, 이전 요청 취소, 최신 질의와 열린 메뉴 확인을 적용했습니다. 조회 오류, 재시도, 검색 결과 없음을 구분합니다.
3. 대표 칩 위에 `GenreCombobox`를 추가했습니다. 편집 가능한 앵커는 Material 3를 사용하고 메뉴 위치는 입력 아래로 고정했습니다. IME와 화면 아래 인셋을 제외한 높이에 맞춰 스크롤합니다. 장르 항목은 기존 입력 높이 토큰으로 40dp에 맞추고 항목 사이에 기존 여백 토큰으로 4dp 간격을 뒀습니다. 주인공과 주변 인물의 특징 직접 입력은 유지했습니다.
4. 검색 항목은 칩과 같은 선택 상태를 토글합니다. 대표 장르는 원래 위치를 유지하고 대표 목록 밖의 장르만 처음 선택할 때 마지막에 추가합니다. 추가 칩의 위치는 선택 해제와 재선택에도 유지합니다. 최대 3개에서는 새 선택만 제한하고 기존 선택 해제는 허용하며 검색어, 메뉴, 키보드를 닫습니다.
5. 추가 칩 ID 순서를 기존 초안 JSON에 저장합니다. 기존 JSON의 누락 필드는 빈 목록입니다. Room 테이블 변경은 없습니다. 이전 동작으로 추가 목록에 저장된 대표 장르는 복원 시 추가 목록에서 제외하고 대표 위치에 표시하며 선택 상태는 보존합니다. 이전 직접 입력 중 정식 이름과 일치하는 항목은 제공 ID로 변환하고 나머지 원문은 초안에 보존합니다. 새 생성 요청은 제공 ID만 사용합니다. 기존 진행 중 요청의 복구 명령은 유지합니다.
6. 스토리라인 단계의 키워드 이름 복원에 전체 카탈로그를 사용합니다.
7. 빈 검색어는 기존 전체 카탈로그를 재사용하며, 초기 카탈로그를 받는 중 열면 같은 요청을 기다립니다. 성공한 검색 결과는 빈 결과를 포함해 서로 다른 검색어 20개까지 ViewModel 수명의 메모리에 저장하고 가장 먼저 조회한 항목부터 제거합니다. 오류는 캐시하지 않습니다. 구성 변경에는 유지되며 새 화면의 ViewModel이나 프로세스 재시작에서는 새로 조회합니다.
8. 캐시에 없는 검색은 새 결과를 받을 때까지 기존 목록을 유지합니다. 기존 250ms 입력 대기를 제외하고 실제 요청이 200ms에 도달하면 로딩 문구를 표시합니다. 결과가 아직 없으면 높이만 유지하고 결과 없음 문구를 먼저 표시하지 않습니다. 요청 완료, 입력 변경, 선택, 메뉴 닫기는 타이머와 로딩 표시를 해제합니다.

## 검증

- 200ms 최종 기준 조정 후 `:create:compileDebugKotlin`, `:create:ktlintCheck`, `:create:detekt`와 `GenreSearchLoadingTest` 9개를 통과했습니다. 199ms에는 숨기고 200ms에 표시하며 검색어 변경 시 타이머를 다시 시작하는 경계를 확인했습니다. 로그: `/tmp/knk1543-loading-200-verification.log`.
- 2026-10-05 현재 PC 네트워크에서 공개 dev 장르 API를 전체 목록, `로맨스`, `ㄴㄹ`, `판타지` 순으로 5회 반복해 총 20회 순차 측정했습니다. 첫 연결 후 같은 curl 프로세스의 연결을 재사용했고 모두 HTTP 200이었습니다. 평균 21.33ms, 중앙값 15.62ms, 표본 p95 39.48ms, 최대 88.44ms였습니다. 기기 렌더링과 모바일 네트워크 시간은 포함하지 않으며, 초기 기준은 300ms였으며 사용자 요청으로 최종 기준을 200ms로 조정했습니다. 원자료: `/tmp/knk1543-genre-latency.json`.
- 캐시 회귀 테스트 4개가 수정 전 실제 상태와 요청 횟수 차이로 실패하고 수정 후 통과했습니다. 이후 100ms 빠른 응답의 로딩 미표시, 299ms와 300ms 경계, 입력 변경과 닫기의 취소, 닫힌 메뉴와 공유 카탈로그 작업의 독립 수명, 20개 상한과 새 화면의 재조회를 추가했습니다. 로그: `/tmp/knk1543-loading-red.log`, `/tmp/knk1543-loading-green.log`, `/tmp/knk1543-loading-verification.log`.

- `:create:compileDebugKotlin`, `:create:ktlintCheck`, `:create:detekt`, `:create:testDebugUnitTest`: 캐시와 지연 로딩 수정 후 통과, 143개 테스트. 메뉴 함수의 복잡도 검사 실패는 상태 표시와 결과 항목을 분리한 뒤 재검증해 통과했습니다.
- `:designsystem:ktlintCheck`, `:designsystem:detekt`: 통과.
- `:app:installDebug`: Pixel_10 API 37 에뮬레이터 설치 통과.
- 자동 검증에 검색 응답 순서 역전, 연속 입력 대기, 선택과 중복 방지, 최대 선택 개수, 검색 실패와 빈 결과, 초안 순서와 선택 해제의 JSON 왕복, 이전 직접 입력의 요청 제외를 포함했습니다.
- 선택 토글 회귀는 수정 전 `GenreSearchTest` 10개 중 5개가 실제 상태와 순서 불일치로 실패하는 것을 확인한 뒤 수정했습니다. 대표 칩 선택 후 검색에서 해제, 검색에서 대표 장르 최초 선택 시 원래 위치 유지, 비대표 칩의 해제와 재선택 순서, 3개 선택 중 해제, 이전 초안의 잘못된 대표 추가 ID를 양쪽 로드 순서에서 정규화하는 경우를 모두 통과했습니다. 로그: `/tmp/knk1543-toggle-red.log`, `/tmp/knk1543-toggle-green.log`, `/tmp/knk1543-toggle-verification.log`.

- 전체 `check`와 CI는 실행하지 않았습니다.

## 복구와 후속

클라이언트 변경을 되돌려도 추가된 JSON 필드는 기존 디코더가 무시합니다. 서버가 장르 직접 입력을 이미 종료했으므로 구버전 직접 입력 UI로의 단순 복귀는 새 요청 실패를 되살릴 수 있습니다. 일반 제작과 수정 입력은 KNK-1521 화면 구현 시 같은 제공 장르 계약에 연결합니다.
