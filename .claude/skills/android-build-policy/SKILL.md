# 빌드 정책

## 목적

빌드 구성이 로컬과 CI에서 재현되고, 잘못된 구성이 조용히 통과하지 않게 합니다.

## 확인할 핵심

실제 값을 `gradle/libs.versions.toml`, 모듈 빌드 파일, Gradle wrapper·daemon 설정, CI에서 읽습니다. 버전 표를 이 스킬에 복사하지 않습니다.

- Gradle daemon JDK와 CI JDK가 맞는가
- Kotlin·Compose·AGP 등 함께 움직이는 플러그인 조합이 맞는가
- 경고·정적 검사 실패 정책과 억제 이유가 명확한가
- 범위 버전 없이 중앙에서 의존성을 관리하는가
- 생성 코드 실패가 해당 빌드 실패로 이어지는가
- 새 모듈이 역할에 필요한 정적 검사·lint·테스트와 CI 리포트 수집에 연결되는가
- 구성 캐시·빌드 캐시를 끄는 대신 비호환 구성을 고쳤는가
- CI와 로컬에서 같은 작업을 재현할 수 있는가

## 변경별 완료 조건

- 새 모듈 추가: 필요한 플러그인과 검사·테스트 작업이 루트 CI 게이트에서 실행되고 리포트 경로가 특정 모듈에 고정되지 않았는지 확인합니다. 로컬 완료 조건은 새 모듈과 직접 소비 모듈의 관련 작업으로 제한하고 전체 게이트는 CI에 맡깁니다.
- 버전·플러그인 변경: 영향받는 모듈과 variant를 컴파일합니다.
- 코드 생성 도구 추가: 증분 상태에 기대지 않는 빌드를 한 번 확인합니다.
- 축소 설정 변경: 축소가 켜진 해당 variant를 만듭니다.
- 캐시 문제 진단: 캐시를 비우는 검증은 원인을 가를 때 한 번만 사용합니다.
- 전체 variant 빌드는 출시 준비나 공통 빌드 로직 변경에만 요구합니다.

일반 코드 변경에 전체 빌드 정책 감사를 붙이지 않습니다.

## 작업 흐름

1. 실제 구성과 `docs/plans/_project.md`의 빌드 결정을 읽습니다.
2. 요청과 직접 관련된 항목만 검사합니다.
3. 확인된 불일치와 선택이 필요한 정책을 나눠 보고합니다.
4. 변경 후 검증은 `android-change-verification`으로 가장 작은 관련 작업을 선택합니다.
5. 프로젝트 공통 정책이 바뀐 경우에만 `_project.md`를 갱신합니다.
