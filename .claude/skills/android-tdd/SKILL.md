# 테스트 우선 구현

## 목적

관찰 가능한 행동을 테스트로 고정한 뒤 최소 구현으로 통과시킵니다. 테스트 유무와 범위는 변경 위험을 기준으로 정하며 테스트를 만들기 위한 구조 확장을 최소화합니다.

## 적용

- 명시적인 TDD 요청
- 재현 가능한 회귀 버그
- 인증·데이터 변환·삭제·전송처럼 실패 비용이 큰 로직

단순 표시, 프레임워크 배선, 이미 충분히 덮인 리팩터링에는 강제하지 않습니다.

## 흐름

1. 요구사항을 입력·행동·기대 결과로 바꿉니다.
2. 하나의 행동 묶음을 검증하는 가장 작은 테스트를 작성합니다.
3. 기대한 이유로 실패하는지 관련 테스트만 실행합니다. 컴파일·설정 실패는 재현 성공으로 보지 않습니다.
4. 테스트를 통과시키는 최소 구현을 합니다.
5. 같은 행동 묶음의 경계값을 필요한 만큼 추가하고 관련 테스트를 다시 실행합니다.
6. 최종 검증 범위는 `android-change-verification`에 맡깁니다.

테스트 케이스마다 Gradle을 다시 시작하지 않습니다. 한 행동을 설명하는 경계값은 한 번의 red-green 주기로 묶을 수 있습니다.

## Android 비동기 테스트

- 디스패처와 시간을 주입해 실제 대기를 없앱니다.
- 취소와 오류를 구분하고 상태 전이의 필요한 중간 상태만 검증합니다.
- UI 테스트는 사용자가 보는 의미와 동작을 대상으로 하며 내부 구현에 결합하지 않습니다.
- 불안정성을 재시도로 감추지 않습니다.
