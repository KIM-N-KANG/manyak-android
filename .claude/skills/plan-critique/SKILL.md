# 계획 적대적 검토

## 목적

계획을 구현했을 때 재작업을 만드는 가정과 누락만 찾습니다. 문장 형식이나 일반적인 모범 사례는 지적하지 않습니다.

## 검토 범위

계획 문서를 우선 근거로 사용하고, 계획이 참조하는 코드와 프로젝트 결정만 필요한 만큼 확인합니다. 라우팅이 의심될 때만 관련 스킬 설명을 확인하며 스킬 디렉터리 전체를 다시 읽지 않습니다.

다섯 방향으로 공격합니다.

1. **범위와 근거** — 결정이 실제 요구와 코드에 근거하며 불필요한 확장을 만들지 않는가
2. **계약과 실패** — 서버·저장소·인증·외부 입력 실패가 즉석 결정으로 남지 않았는가
3. **순서와 가역성** — 숨은 의존 때문에 뒤 단계가 앞 단계를 버리게 하지 않는가
4. **완료와 검증** — 완료 조건이 관찰 가능하고 검증 비용이 위험에 비례하는가
5. **미결정** — 지금 정할 수 있는 일을 미뤘거나 외부 합의가 필요한 값을 임의로 확정하지 않았는가

## 심각도

| 등급 | 기준 |
| --- | --- |
| 재설계 | 구현하면 구조·계약·데이터를 버리고 다시 만들어야 합니다 |
| 보완 | 현재 구조를 유지한 채 계획에 빠진 내용을 추가할 수 있습니다 |
| 확인 | 구현 중 확인해도 재작업 가능성이 낮습니다 |

## 보고

각 발견에는 상황, 예상 결과, 고칠 계획 위치를 적습니다. 발견이 없으면 공격한 범위와 확인하지 못한 근거를 밝힙니다. 가장 큰 위험은 하나만 고릅니다.

리뷰만 요청받았다면 계획이나 코드를 직접 수정하지 않습니다. 계획 작성·구현 작업 안에서 호출됐다면 발견을 원래 작업 범위 안에서 반영하고, 범위를 넓히는 변경만 사용자에게 확인합니다.
