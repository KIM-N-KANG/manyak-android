# 디바이스·다국어·접근성

## 목적

안드로이드 앱 개발 고려 사항 8개 항목 중 6번 **디바이스·다국어·접근성**을 담당합니다. 아래 6개 결정 항목을 각각 명시적으로 결정하거나, 기존 화면이 이미 내린 결정을 확인하고 위반을 지적합니다.

| 결정 항목 | 결정할 내용 |
| --- | --- |
| 1. 창 크기 대응 | 화면 크기, 가로 모드, 태블릿, 폴더블에 어떻게 대응할지 |
| 2. 시스템 영역 | 키보드·상태 표시줄·내비게이션 바 영역을 어떻게 처리할지 |
| 3. 폰트 확대 | 시스템 폰트 크기가 커졌을 때 레이아웃을 어떻게 유지할지 |
| 4. 지역화 | 문자열·날짜·시간·숫자·복수형을 어떻게 지역화할지 |
| 5. 번역문 길이와 RTL | 길어진 번역문과 오른쪽에서 왼쪽으로 읽는 언어에 어떻게 대응할지 |
| 6. 접근성 | 화면 낭독, 포커스 순서, 터치 영역, 색상 대비를 어떻게 보장할지 |

## 두 가지 전제

### 기기 종류가 아니라 사용 가능한 공간으로 판단합니다

"태블릿인가"가 아니라 "지금 이 창의 폭이 얼마인가"로 분기합니다. 분할 화면에서는 태블릿도 좁고, 폴더블은 접고 펴는 동안 같은 기기가 다른 크기가 됩니다. 기기 종류로 분기하면 이 경우들이 전부 어긋납니다.

### 사용자가 시스템에 알려준 설정을 앱이 무시하지 않습니다

폰트 크기, 표시 크기, 언어, 애니메이션 축소, 다크 모드는 사용자가 이미 밝힌 요구입니다. 텍스트 크기를 고정하거나 자체 언어 설정만 쓰는 것은 그 요구를 덮는 결정이며, 그렇게 하려면 이유가 있어야 합니다.

## 적용 범위 판단

요청 규모에 맞는 항목만 검토합니다.

| 요청 | 검토할 항목 |
| --- | --- |
| 화면 레이아웃 신규 설계, 화면 감사 | 1~6 전부 |
| 기존 화면에 요소 추가 | 3, 5, 6 |
| 태블릿·폴더블·가로 모드 대응 | 1, 2 |
| 화면이 가려지거나 키보드에 밀리는 문제 | 2 |
| 문자열 추가, 다국어 도입 | 4, 5 |
| 접근성 점검·개선 | 6 |

## 이미 결정된 항목

아래 판단 기준 중 일부는 프로젝트에서 한 번 정하면 모든 기능에 그대로 적용됩니다. 그런 항목은 `docs/plans/_project.md`를 먼저 확인합니다.

- **결정이 있으면 다시 결정하지 않습니다.** 결정을 읽고, 이 요청의 코드가 그것을 지키는지만 봅니다. 어긋나면 위반으로 보고합니다. 결정 자체를 바꿔야 하면 이유와 함께 `_project.md`를 갱신합니다.
- **결정이 없으면 여기서 정하고 그 결과를 `_project.md`에 남깁니다.** 남기지 않으면 다음 기능이 같은 결정을 처음부터 다시 하고, 기능마다 구조가 갈립니다.

이 문서를 이미 읽었다면 다시 열지 않고 그 내용을 씁니다.

| 구분 | 항목 |
| --- | --- |
| 프로젝트에서 한 번 결정 | 1의 지원 창 크기와 대응 전략, 2 시스템 영역, 3 폰트 확대, 4 지역화 규칙 |
| 기능마다 판단 | 1의 개별 화면 레이아웃, 5 번역문 길이와 RTL, 6 접근성 |

## 결정 항목별 판단 기준

### 1. 창 크기 대응

- **분기 기준을 창 크기로 정합니다.** 폭과 높이를 따로 봅니다. 높이가 낮은 경우(가로로 돌린 폰)는 폭만 보면 잡히지 않습니다.
- **분기 단계 수를 정합니다.** 좁음·보통·넓음 세 단계가 흔한 시작점입니다. 단계를 늘릴수록 확인해야 할 조합이 늘어납니다.
- **단계마다 레이아웃이 어떻게 달라지는지 정합니다**: 한 열에서 목록·상세 두 열로, 하단 탐색에서 측면 탐색으로, 전체 화면 대화상자에서 작은 대화상자로.
- **넓은 화면에서 그냥 늘리지 않습니다.** 한 줄이 길어지면 읽기 어렵습니다. 최대 폭을 제한하거나 열을 추가합니다.
- **레이아웃이 합쳐지면 백스택 의미가 달라집니다.** 좁은 창에서 목록과 상세가 두 화면인데 넓은 창에서 한 화면이 되면, 창 크기가 바뀔 때 백스택을 어떻게 옮길지 정해야 합니다. 정하지 않으면 펼친 직후 뒤로 가기가 엉뚱한 화면으로 갑니다. 라우트 구성은 고려 사항 1번 항목 스킬과 함께 정합니다.
- **가로 모드 지원 여부를 명시적으로 결정합니다.** 막기로 했다면 이유를 적습니다. 기기를 거치대에 고정해 쓰는 사용자에게 방향 고정은 접근성 문제가 됩니다.
- **폴더블은 별도 분기가 아니라 창 크기 변화입니다.** 접기·펴기는 구성 변경이므로 상태 유지가 필요하며, 고려 사항 2번 항목 스킬의 결정과 이어집니다. 화면 중앙 접힘 부분에 중요한 조작 요소가 걸리지 않게 합니다.
- **크기가 바뀔 때 스크롤 위치와 입력값이 유지되는지 확인합니다.** 레이아웃 분기만 맞추고 상태를 놓치면 회전할 때마다 처음으로 돌아갑니다.

### 2. 시스템 영역

- **화면을 시스템 바 아래까지 그릴지 정합니다.** 가장자리까지 그리는 것이 기본 방향이므로, 콘텐츠가 상태 표시줄과 내비게이션 바에 가려지지 않도록 여백을 따로 적용해야 합니다.
- **여백을 어디에 줄지 정합니다.** 배경은 화면 전체에 그리고 여백은 콘텐츠에만 주는 것이 기본입니다. 최상위에 한 번에 여백을 주면 목록이 시스템 바 아래로 스크롤되는 표현을 잃습니다.
- **스크롤 목록의 마지막 항목이 내비게이션 바에 가리지 않는지 확인합니다.** 목록 끝 여백은 가장 자주 빠지는 부분입니다.
- **키보드가 올라올 때의 동작을 정합니다**: 입력 필드를 밀어 올릴지, 화면을 스크롤할지, 하단 버튼을 키보드 위로 붙일지. 키보드 높이 변화에 따라 부드럽게 따라가는지 확인합니다.
- **제스처 탐색과 버튼 탐색을 모두 확인합니다.** 하단 여백과 화면 가장자리 스와이프 동작이 탐색 방식에 따라 달라집니다.
- 노치·펀치홀과 둥근 모서리에 중요한 요소가 걸리지 않게 합니다.

### 3. 폰트 확대

- **텍스트 크기에 확대되는 단위를 씁니다.** 고정 크기를 쓰면 사용자의 폰트 설정이 무시됩니다. 아이콘과 여백은 고정 단위를 쓰되 텍스트는 확대 단위를 씁니다.
- **최대 설정에서 확인합니다.** 시스템 폰트 크기와 표시 크기는 별개 설정이며 둘 다 최대로 두면 예상보다 훨씬 커집니다.
- **높이를 고정한 컨테이너를 최소 높이로 바꿉니다.** 고정 높이는 큰 글씨에서 텍스트를 자르거나 넘치게 합니다.
- **줄 수 제한이 핵심 정보를 자르지 않는지 확인합니다.** 한 줄 고정은 큰 글씨에서 가장 먼저 문제가 됩니다. 어디까지 잘라도 되는지 요소마다 정합니다.
- **아이콘과 텍스트가 나란한 요소의 정렬**을 확인합니다. 텍스트만 커지면 정렬이 깨집니다.
- **화면 전체가 넘칠 때 스크롤할 수 있는지 확인합니다.** 스크롤 없는 화면은 큰 글씨에서 하단 버튼에 닿을 수 없게 됩니다.

### 4. 지역화

- **문자열을 코드에 직접 쓰지 않습니다.** 리소스로 분리하지 않으면 나중에 전수 조사를 해야 합니다. 다국어 계획이 없어도 이 규칙은 유지합니다.
- **문장을 조각내어 이어 붙이지 않습니다.** 언어마다 어순이 다르므로 조각 합성은 번역할 수 없습니다. 자리 표시자를 포함한 완전한 문장을 하나의 리소스로 둡니다.
- **복수형은 복수형 리소스로 처리합니다.** 언어마다 복수 규칙의 개수가 다릅니다. 개수를 직접 분기해 문자열을 고르면 다른 언어에서 틀립니다.
- **날짜·시간·숫자·통화는 지역 형식 기능으로 표시합니다.** 형식 문자열을 직접 만들면 지역마다 어긋납니다.
- **시각의 기준을 정합니다.** 서버는 절대 시각을 주고 표시는 기기 시간대로 합니다. 상대 시간 표시를 쓸지, 쓴다면 언제 갱신할지도 정합니다.
- **지원 언어 목록과 미지원 언어의 기본 언어를 정합니다.**
- **번역이 빠진 문자열은 기본 언어로 표시됩니다.** 한 화면에 두 언어가 섞이므로, 언어를 추가할 때 누락된 문자열을 어떻게 찾을지 정합니다.
- **앱 안에서 언어를 바꾸게 할지 결정합니다.** 시스템 언어만 따를지, 앱별 언어 설정을 제공할지. 제공하면 설정 변경 시 화면 갱신 경로가 필요합니다.

### 5. 번역문 길이와 RTL

- **번역문은 원문보다 길어진다고 가정합니다.** 버튼, 탭 라벨, 칩처럼 폭이 좁은 요소가 먼저 깨집니다.
- **길이 검증 방법을 정합니다.** 가장 긴 지원 언어로 전 화면을 확인하거나, 길이를 늘린 의사 번역으로 확인합니다. 번역 전에 레이아웃을 확정하면 반드시 다시 손봐야 합니다.
- **잘림 처리 방식을 요소마다 정합니다**: 줄바꿈, 말줄임, 폭 확장 중 무엇을 허용할지.
- **RTL 지원 여부를 명시적으로 결정합니다.** 지원 언어 목록에 RTL 언어가 없다면 지원하지 않는다고 적습니다.
- **지원한다면 좌우 대신 시작·끝 기준으로 여백과 정렬을 지정합니다.** 방향성이 있는 아이콘(뒤로 가기, 진행 방향)은 뒤집고, 숫자와 시계, 재생 진행 방향처럼 뒤집으면 안 되는 것은 그대로 둡니다.

### 6. 접근성

- **조작 가능한 모든 요소에 설명을 붙입니다.** 아이콘만 있는 버튼이 가장 흔한 누락입니다. 반대로 장식용 이미지는 낭독 대상에서 제외합니다.
- **낭독 순서가 화면에서 보이는 순서와 맞는지 확인합니다.** 겹쳐 배치하거나 자유 배치한 영역에서 어긋납니다. 함께 읽혀야 의미가 통하는 요소는 하나로 묶습니다.
- **상태 변화를 알립니다**: 선택됨, 펼쳐짐, 로딩 중, 오류 발생. 시각적 표현만 있으면 낭독 사용자는 아무 일도 일어나지 않은 것으로 인식합니다.
- **터치 영역 최소 크기를 보장합니다.** 아이콘이 작더라도 터치 영역은 따로 확보합니다.
- **색상 대비 기준을 정하고 확인합니다.** 비활성 상태, 플레이스홀더, 이미지 위 텍스트가 자주 미달합니다.
- **밝은 테마와 어두운 테마 양쪽에서 대비를 확인합니다.** 한쪽 기준으로 고른 색이 다른 쪽에서 미달하는 경우가 흔합니다.
- **색만으로 정보를 전달하지 않습니다.** 오류를 색으로만 표시하면 구분하지 못하는 사용자가 있습니다. 문구나 아이콘을 함께 씁니다.
- **키보드와 스위치 조작으로 모든 기능에 도달할 수 있는지 확인합니다.** 포커스 이동 순서와 현재 포커스 표시가 필요합니다.
- **애니메이션 축소 설정을 존중합니다.** 큰 화면 전환 움직임은 어지럼증을 유발할 수 있습니다.
- **자동으로 사라지는 안내와 시간 제한이 있는 조작**은 읽는 속도가 다른 사용자를 배제합니다. 지속 시간을 늘리거나 다시 볼 경로를 둡니다.

## 작업 흐름

1. **지원 범위를 먼저 확정합니다**: 지원 언어 목록, RTL 지원 여부, 가로 모드 지원 여부, 대응할 최소·최대 창 크기. 이 범위가 없으면 이후 결정에 기준이 없습니다.
2. **창 크기 분기와 단계별 레이아웃 변화를 정합니다.**
3. **시스템 영역 여백과 키보드 동작을 정합니다.**
4. **폰트 최대 설정에서 깨지는 지점을 찾고 요소별 잘림 규칙을 정합니다.**
5. **문자열과 형식 처리 규칙을 정합니다.** 조각 합성과 직접 포맷이 남아 있는지 확인합니다.
6. **접근성 요구를 화면 요소별로 배정합니다.** 설명, 낭독 순서, 터치 영역, 대비를 각각 확인합니다.
7. **검증 시나리오를 실행합니다.** 아래 표는 대부분 기기 설정만으로 확인할 수 있으므로, 실행하지 않았다면 통과로 적지 않습니다.
8. **결정할 수 없는 항목은 미결정으로 남기고, 코드 변경은 사용자 승인 후에 합니다.**
