# 구성 변경 대응

## 전제

`android:configChanges`를 선언하지 않으면 아래 축이 바뀔 때마다 **Activity가 재생성되고 컴포지션이 통째로 다시 만들어집니다.** 선언해서 재생성을 막는 쪽은 리소스 재적용을 손으로 재현해야 하므로 기본값이 아닙니다. 이 스킬은 재생성을 수용한 상태에서 무엇이 깨지는지 다룹니다.

| 자주 | 바뀌는 축 |
| --- | --- |
| 화면 회전 | `orientation` + `screenSize` + `screenLayout` |
| 멀티윈도우·분할 화면 크기 조절, PiP 전환 | `screenSize` `screenLayout` |
| 폴더블 접기·펼치기, 다른 디스플레이로 이동 | `screenSize` `smallestScreenSize` `density` |
| 시스템 다크 모드 토글 | `uiMode` |
| 시스템 글자 크기, 표시 크기 | `fontScale` `density` |
| 접근성 "굵은 텍스트", 시스템·앱별 언어 | `fontWeightAdjustment` `locale` |

**구성 변경이 아닌 것**: 개발자 옵션 "활동 유지 안 함", 권한 취소, 저메모리 종료는 프로세스가 죽어 ViewModel까지 사라집니다. 증상이 비슷해 보여도 원인과 대응이 다르므로, 점검을 시작하기 전에 `adb shell settings get global always_finish_activities`로 그 옵션이 꺼져 있는지 확인합니다. 켜져 있으면 지금 보는 것은 구성 변경이 아닙니다.

회전만 확인하고 끝내지 않습니다. 재생성은 다크 모드 토글·글자 크기 변경으로도 똑같이 일어나고, 그쪽이 재현하기 더 쉽습니다.

## 무엇이 깨지는지 — 네 갈래

### 1. 부수효과가 재생성마다 다시 실행됨

가장 많이 놓치는 갈래입니다. `LaunchedEffect(key)`는 키가 **바뀔 때**가 아니라 **컴포지션에 들어올 때마다** 실행됩니다. 재생성 직후에도 한 번 더 도는데, 그 사이 `rememberSaveable` 계열이 이미 복원해 둔 값을 효과가 덮어쓰면 사용자는 "복원이 안 된다"고 느낍니다.

- **위치를 되돌리거나 값을 초기화하는 효과**는 직전 값을 들고 실제로 바뀌었는지 비교합니다. 직전 값을 현재 값으로 초기화해 두면 재생성 직후에는 자연히 발동하지 않습니다.
- **경과 시간을 세는 효과**는 화면 안에서 세지 않고 시작 시각을 남겨 두고 뺍니다. 단조 시계를 써야 사용자가 기기 시간을 바꿔도 어긋나지 않습니다.
- **Activity 수명을 백그라운드 신호로 쓰는 곳**(`ON_STOP`에서 저장·정리·전송)은 재생성으로도 발동합니다. `isChangingConfigurations`로 걸러 내지 않으면, 저장하지 않고 나가려던 편집이 화면을 한 번 돌린 것만으로 남습니다.
- **`ON_START`에서 잠금을 풀거나 상태를 되돌리는 복귀 처리**는 그 작업이 아직 살아 있는지 먼저 봅니다. 진행 중인데 잠금이 풀리면 화면이 "아무 일도 없다"고 거짓말하고, 사용자가 다시 눌러도 중복 방지 가드에 막혀 반응이 없습니다.
- 읽지 않은 오류 안내를 복귀 처리가 지우지 않게 합니다. 화면이 다시 만들어졌다고 실패가 없던 일이 되지는 않습니다.

### 2. `remember` 값이 사라짐

무엇을 `rememberSaveable`로 올릴지는 **잃었을 때 사용자가 다시 해야 하는 일**로 판단합니다. 수명 선택 기준 자체는 `state-lifecycle`이 소유하므로 여기서 다시 정하지 않습니다.

- 올립니다 — 입력하던 시트·다이얼로그의 대상, 진행 단계, 사용자가 친 값. 시트가 닫히면 그 안의 입력도 함께 버려집니다.
- 그대로 둡니다 — 메뉴 펼침, 툴팁, 측정값처럼 다시 열거나 다시 재면 되는 것.
- 직렬화가 안 되는 타입은 타입에 직렬화를 붙이는 대신 화면 쪽에 좁은 `Saver`를 둡니다. 값이 몇 개뿐이면 그쪽이 가볍습니다.

### 3. 뷰 시스템 객체가 새로 만들어짐

`AndroidView`의 `factory`는 재생성에서 다시 실행되어 **새 View 인스턴스**를 만듭니다. `WebView`처럼 스스로 상태를 들고 있는 뷰는 그대로 두면 문서를 처음부터 다시 읽고 읽던 위치가 사라집니다.

상태를 넘기려면 저장 **시점**이 맞아야 합니다. `onRelease`는 컴포지션이 이미 걷힌 뒤라 늦습니다. 살아 있는 뷰에서 상태를 뜨는 `Saver`를 쓰면 저장이 필요한 순간에 정확히 뜹니다.

인스턴스가 새로 만들어진다는 것은 **재로드를 막으려고 View에 걸어 둔 표시도 같이 사라진다**는 뜻입니다. `tag`처럼 View에 토큰을 심어 두고 비교하는 가드는 새 인스턴스에서 늘 빈 값이라 그냥 통과합니다. 복원을 붙일 때 이 가드를 함께 고치지 않으면 복원한 상태를 곧바로 덮어씁니다.

### 갈래는 서로 가립니다

한 갈래를 고치면 그것이 가려 주던 다른 갈래가 드러날 수 있습니다. 재생성마다 돌던 자동 저장을 걸러 내면, 그동안 그 저장이 우연히 지켜 주던 입력이 이제 실제로 사라집니다. 고친 뒤에 그 화면을 한 번 더 훑습니다.

### 4. Activity 참조가 죽음

호출 시점에 잡아 둔 Activity는 재생성에서 무효가 됩니다. 다만 **결과를 기다리는 continuation이 Activity가 아니라 SDK·프레임워크 콜백에 물려 있고 해제가 `finally`에 있으면 잠금은 정상적으로 풀립니다.** 코드를 먼저 읽고, 잠금이 실제로 남는 것을 본 뒤에 손댑니다. 재현 없이 "Activity가 죽으면 실패 처리" 같은 방어 코드를 넣으면 완료된 인증·결제를 버리는 더 나쁜 문제를 만듭니다.

## 기기 확인

빌드해 설치한 뒤, **바뀌기 직전과 직후를 같은 조건에서 캡처해 비교**합니다. 눈으로 보고 넘기면 스크롤이 몇 픽셀 튄 것이나 버튼이 비활성으로 바뀐 것을 놓칩니다.

| 축 | 명령 |
| --- | --- |
| 다크 모드 | `adb shell cmd uimode night yes` / `no` |
| 회전 | `adb shell settings put system accelerometer_rotation 0` 후 `user_rotation 1` / `0` |
| 글자 크기 | `adb shell settings put system font_scale 2.0` / `1.0` |
| 화면 캡처 | `adb exec-out screencap -p > before.png` |
| 포커스·키보드 | `adb shell dumpsys input_method \| grep mInputShown` |

절차는 이렇습니다.

1. `always_finish_activities`가 꺼져 있는지 확인합니다.
2. 점검할 화면을 사용 중인 상태로 만듭니다 — 스크롤을 내리고, 값을 입력하고, 시트를 열어 둡니다. 초기 상태로는 아무것도 드러나지 않습니다.
3. 캡처 → 축 하나 토글 → 캡처.
4. 두 장을 비교합니다. 스크롤 위치, 입력값, 열려 있던 것, 진행 표시, 버튼 활성 여부를 봅니다.
5. 원래 값으로 되돌립니다. 기기 설정을 바꾼 채 두지 않습니다.

**의도한 동작이 살아 있는지도 함께 확인합니다.** 재생성에서 발동하지 않게 고친 효과가 원래 상황에서는 여전히 발동해야 합니다.

## 넘기는 것

- 상태 수명·복원 범위를 새로 정하는 결정 — `state-lifecycle`
- 가로·큰 글자에서 레이아웃이 잘리거나 스크롤이 없는 문제 — `adaptive-ui`
- 검증 실행 계획과 수준 선택 — `android-change-verification`에 `state-restore` 태그로 넘깁니다

## 완료 보고

- 점검한 화면과 축을 알립니다.
- 갈래별로 찾은 것과, 확인했지만 문제가 없던 것을 함께 보고합니다.
- 기기에서 확인한 것과 코드로만 판단한 것을 구분합니다.
- 되돌린 기기 설정과, 테스트하며 만든 데이터가 남아 있으면 알립니다.
