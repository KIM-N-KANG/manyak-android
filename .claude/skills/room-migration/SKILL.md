# Room 마이그레이션

## 필수 확인

1. 현재와 변경 후 exported schema를 대조합니다.
2. 지원하는 설치 버전 범위와 현재 버전까지의 마이그레이션 경로를 확인합니다.
3. 기존 행이 새 null·기본값·외래 키·타입 규칙을 만족하는지 판단합니다.
4. 변환할 수 없는 데이터와 장시간 마이그레이션의 사용자 영향을 정합니다.

스키마 내보내기, DB 버전, 마이그레이션 코드는 같은 변경에 포함되어야 합니다.

## 데이터 보존

- null 불가 컬럼과 새 외래 키에는 기존 행 처리 규칙이 필요합니다.
- 컬럼 삭제·이름·타입 변경은 데이터 복사 또는 명시적 폐기 근거가 필요합니다.
- 기본값 변경이 기존 행에 자동 적용된다고 가정하지 않습니다.
- 운영 데이터가 유일한 원본이면 파괴적 대체를 사용하지 않습니다.
- 서버에서 다시 받을 수 있는 캐시 DB만 명시적 근거와 운영 variant 확인이 있을 때 재생성을 허용합니다.

## 검증

관련 마이그레이션 테스트는 이 변경의 로컬 필수 검증입니다. 대표 데이터를 이전 schema에 넣고 업그레이드한 뒤 값과 제약을 확인합니다. 여러 이전 버전을 지원하면 각 시작 버전에서 현재 버전까지의 경로를 확인합니다.

전체 `check`와 패키징은 CI에 맡기고 `db-migration` 위험 태그를 `android-change-verification`에 전달합니다.

실패 시 앱 시작을 막는지, 캐시를 안전하게 다시 만들 수 있는지, 사용자에게 어떤 복구 경로가 있는지도 함께 결정합니다.
