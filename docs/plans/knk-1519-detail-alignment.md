# KNK-1519 세부 동작 정합

## 목표와 분석

[KNK-1519](https://kimandkang.atlassian.net/browse/KNK-1519)의 간편 제작, 채팅, 마이 화면 차이를 공통 계약에 맞춥니다. 하네스와 Android 모두 `fix/KNK-1519-align-creation-chat-my-details`에서 작업합니다.

- Android 분기 기준: fetch한 `origin/dev`의 `fdc7d865dd1bf8f2312a0c529b2ee49a2a1d2d50`.
- 하네스 분기 기준: fetch한 `origin/dev`의 `1648e85f0dc2b95f39c7ce9389b0d528184345b7`. 관련 정본이 이 커밋에 포함된 것을 확인했습니다.
- 기존 두 작업 트리는 깨끗했으며 별도 변경을 이동하거나 삭제하지 않았습니다.
- 서버 `ChatService`의 목록 및 상세는 공개 스냅샷이 없으면 제목을 비우면서 원본 스토리 ID를 유지할 수 있습니다. 웹은 제목도 검사하지만 앱은 ID만 검사했습니다. API나 저장 스키마 변경 없이 소비 조건을 맞춥니다.
- 공통 계약은 [클라이언트 spec](../../../knk-harness/docs/spec/3-1-client-spec.md), 플랫폼 예외는 [Android spec](../../../knk-harness/docs/spec/3-3-android-spec.md), 내부 소유권은 [Android design](../../../knk-harness/docs/design/1-2-android-design.md)을 따릅니다.

## 작업별 구현

| 티켓 항목 | 분석과 반영 |
| --- | --- |
| 1 | 인물 ID별 접기 상태를 ViewModel에 보관합니다. 새 항목은 펼침이며 카테고리 이동과 구성 변경에서 유지됩니다. create 내부 `CollapsibleInputHeader`와 높이 애니메이션을 사용합니다. 접힌 항목 다음 머리 줄에는 목록 간격을 두지 않습니다. Android는 스토리라인 진입 뒤 키워드 복귀 경로가 없고 별도 초안 재개 시 펼침으로 시작합니다. |
| 2 | 이름, 성별, 제공 특징, 직접 추가한 특징이 있으면 삭제를 확인합니다. 선택을 해제한 직접 특징도 작성 내용으로 보호합니다. 빈 인물은 즉시 삭제합니다. 다이얼로그 틀은 기존 designsystem 컴포넌트를 쓰고 문자열은 create에 둡니다. |
| 3 | 키워드 미저장 편집에서 실제 저장 레코드가 있는지 확인해 입력 소실과 저장 이후 편집 소실 문구를 구분합니다. |
| 4 | 로컬 카드가 없는 로딩 및 오류에서는 FAB를 숨깁니다. 로컬 카드가 있으면 FAB를 유지하는 기존 제작 카드 설계를 Android 예외로 명시합니다. |
| 5 | 목록과 채팅방 모두 ID 및 공백이 아닌 제목이 있을 때만 신고와 새 채팅을 허용합니다. 메뉴와 ViewModel 요청 경로를 함께 검사합니다. |
| 6 | 일반 입력의 강조 표기 삽입 뒤 Intent를 보내 `client_chat_situationInsertButton_clicked`를 기록합니다. 프로퍼티는 `chat_id`이며 원문은 수집하지 않습니다. |
| 7 | 추천 채우기 확인의 취소 문구를 변경했으나, 후속 사용자 요청으로 기존 "닫기"로 복원했습니다. |
| 8 | 기타 섹션에서 서비스 안내를 피드백 위에 둡니다. |
| 9 | 계정 연동 취소 문구를 변경했으나, 후속 사용자 요청으로 기존 "닫기"로 복원했습니다. |
| 10 | 광고 동의 결과 전송자에 "(팀명 김앤강)"을 포함합니다. |
| 11 | 캐시가 없는 프로필 조회 중 연동 Chip 골격 두 개를 표시합니다. 초대 보상 지급과 닫기 기록 저장 결과를 분리하고, 기록 실패를 안내합니다. 기존의 현재 실행 내 닫힘 동작은 유지하며 닫힌 시트에서 재제출하지 않습니다. |
| 12 | Android spec의 삭제된 스토리 문구와 빈 채팅 목록 CTA 설명을 정정합니다. |
| 13 | 공유 링크 발급은 앱도 기록하고 링크 열람은 웹 전용임을 구분합니다. 상황 삽입을 블럭 추가와 통합한다는 설명을 정정합니다. |

퍼널의 닫기 확인 정책과 "닫기" 라벨은 유지했습니다. 후속 사용자 요청에 따라 인물 삭제 확인을 포함한 이번 작업의 다이얼로그 취소 버튼은 "닫기"로 맞췄습니다. 일반 제작 자체와 새로운 API, DB 마이그레이션은 범위에 포함하지 않습니다.

### 화면 근거와 한계

- 인물 입력은 변경 전 `origin/dev` 소스와 현재 소스를 같은 Compose 테스트 호스트에 렌더링해 `adb exec-out screencap -p`로 캡처했습니다. 실제 회원 데이터나 실제 퍼널 전체 화면의 캡처는 아닙니다.
- 결과는 로컬 [캡처 폴더](../../build/qa/knk-1519)에 있습니다: `before.png`, `after-expanded.png`, `after-collapsed.png`, `after-dark.png`. 비교용 임시 테스트 소스는 제거했습니다.
- 라이트와 다크 테마에서 머리 줄, 화살표, 접힌 행 간격, 남은 인물 입력을 확인했습니다. 다크 캡처는 Compose 테마 전환이며 Activity 재생성 검증은 아닙니다.
- 실제 앱은 최종 `installDebug` 설치와 로그인 화면 실행까지 확인했으며 `final-login.png`를 남겼습니다. 회원 로그인 세션이 없어 마이, 제작 FAB, 삭제된 스토리 메뉴, 계정 연동 및 광고 동의 다이얼로그의 실제 화면 전후 캡처는 미검증입니다.
- 서버의 실제 삭제 응답 재현과 초대 보상 지급은 실행하지 않았습니다. 서버 소스 확인과 fake 응답의 ViewModel 테스트로 판정을 검증했습니다.
- 회전, 글자 크기 변경 및 실제 계정 연동은 미검증입니다. 접기 상태와 삭제 대상이 ViewModel 수명을 따르는 것은 코드로 확인했습니다.
- 전체 `check`와 `assembleDebug`는 CI 소유이므로 로컬에서 반복하지 않았습니다.

## 복구와 다음 검증

API와 저장 스키마 변경이 없어 작업 커밋을 되돌리면 이전 동작으로 복구됩니다. 배포 전에는 로그인한 검증 계정으로 미검증 회원 화면의 전후 캡처, 다이얼로그를 띄운 상태의 Activity 재생성, 서버의 삭제된 스토리 응답과 초대 기록 실패 안내를 확인해야 합니다.
