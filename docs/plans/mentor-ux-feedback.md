# 멘토 UX 피드백 반영 (KNK-1180)

- 계약 정본: 하네스 `3-3-android-app.md` §3-3-3 화면 전환 · 스토리 목록·스토리 상세·채팅 목록의 2026-09-03 결정 기록
- 작성일: 2026-09-03

## 목표

멘토 검수에서 나온 다섯 항목을 순서대로 반영합니다. 각 항목은 공통 결정을 하네스에 먼저 쓰고 이 문서에는 구현 순서와 이 레포가 새로 내린 결정만 남깁니다.

| 순서 | 항목 | 상태 |
| --- | --- | --- |
| 1 | 뒤로가기 화면 전환 효과 변경 | 구현 |
| 2 | 채팅 카드·내 스토리 카드 옵션 다이얼로그(더보기·길게 누르기), 내 스토리 상세 삭제 | 구현 |
| 2-1 | 카드·행·메뉴 항목의 눌림 리플과 길게 누르기 햅틱 | 구현 |
| 3 | 출석체크 탭 당겨서 새로고침 | 미착수 |
| 4 | 스토리 제작 닫기(X)는 항상 확인 다이얼로그 | 미착수 |
| 5 | 응답 생성 중 입력창 탭 시 토스트 안내 | 미착수 |

## 1. 뒤로가기 화면 전환

규칙은 하네스 §3-3-3 화면 전환이 소유합니다. 이 레포가 새로 내린 것은 아래뿐입니다.

- **길이 토큰 `{motion.screen-slide}` 250ms 추가**(`DESIGN.md`). 탭 페이드 150ms 는 그대로 두고 밀기만 따로 둡니다.
- **전환 정의는 `:app`의 `NavTransitions.kt` 한 곳**에 둡니다. `NavDisplay` 세 곳(인증·메인·탭 셸)이 이 파일의 값을 받고, 퍼널 세 목적지는 `entry(metadata = …)`로 축을 고릅니다. 퍼널 판정은 전환 반대편 `Scene`의 마지막 엔트리 키가 퍼널 라우트인지로 합니다 — 라우트 타입만 보므로 `:core:navigation` 외에 새 의존이 생기지 않습니다.
- **예측형 뒤로가기 스펙을 명시**합니다. 라이브러리 기본값(축소 0.7·페이드)을 두면 제스처를 놓는 순간 밀기와 모양이 갈립니다.

### 검증

- `:app:compileDebugKotlin` · `ktlintCheck` · `detekt`(`:app`·`:core:ui`)
- 에뮬레이터에서 `animator_duration_scale`을 늘려 상세 → 뒤로가기, 제작 탭 → 퍼널 → 닫기 중간 프레임 캡처

## 2. 카드 옵션 다이얼로그 · 내 스토리 상세 삭제

규칙은 하네스 §3-3-3의 세 결정 기록(스토리 목록·스토리 상세·채팅 목록, 2026-09-03)이 소유합니다. 이 레포가 새로 내린 것은 아래뿐입니다.

- **옵션 다이얼로그 상단에는 회색 상자 안에 카드 미리보기**를 두고 항목과 8dp 띄웁니다. 목록 카드와 같은 정보를 표지·서체·간격·뱃지 크기만 한 단계씩 작게 그린 `ChatCardPreview`·`MyStoryCardPreview`이고, 회색 상자 위에서 장르 뱃지 바탕이 묻히지 않도록 그 자리만 밝은 알약을 씁니다.
- **옵션 다이얼로그 `ManyakOptionsDialog`와 더보기 버튼 `ManyakMoreButton`을 `:core:ui`에** 둡니다. 채팅 목록과 제작 탭 두 사용처가 동시에 생겨 공용 승격 조건을 만족합니다. 내 스토리 카드의 기존 팝업 메뉴는 이 다이얼로그로 대체했고, 처음 바텀 시트로 만들었다가 내용에 비해 시트 높이가 남아 가운데 다이얼로그로 바꿨습니다.
- **`ChatSummary`에 `storyId`를 추가**합니다. 서버 응답에 있던 값을 카드가 그리지 않아 빼 두었는데, 카드에서 여는 신고의 대상이라 필요해졌습니다.
- **상세 삭제 항목은 응답의 `isOwner`로 엽니다.** 서버는 KNK-1016·1018(2026-08-29)로 `author.nickname`과 상세 `isOwner`를 이미 제공하고 있었고 하네스 `4-backend.md`만 계획 상태로 남아 있어 함께 정정했습니다. 진입 자리를 라우트에 싣는 대안은 서버 판정이 있어 두지 않습니다.
- **다이얼로그 안 "신고하기"·"삭제하기"는 옵션 다이얼로그를 먼저 닫고** 신고 시트·확인 다이얼로그를 엽니다. 신고 대상은 옵션 다이얼로그가 닫혀도 남아야 해서 ViewModel 상태에 `reportStoryId`로 따로 적습니다.
- 삭제된 스토리의 채팅 카드에도 "신고하기"를 남깁니다 — `storyId`는 남아 있고, 읽을 수 없는 스토리는 서버가 404 로 거절해 실패 토스트로 끝납니다. 값이 비어 있을 때만 항목을 숨깁니다.

- **눌림은 테마가 `LocalRippleConfiguration`으로 켠 리플 하나**입니다(`DESIGN.md` 눌림 리플). 처음엔 리플을 끈 채 누르는 동안만 반투명 덮개를 그리는 커스텀 표시를 만들었지만, 톡 치는 탭에서 보이지 않아 유지 시간·페이드를 더했고, 비교해 보니 퍼지는 리플 쪽이 나아 리플로 확정했습니다. 색·농도는 `overlay-pressed` 토큰이 정하고, 탭 바는 기존대로 하위 트리에서 끕니다. 길게 누르기 햅틱은 두 카드의 `onLongClick`에서 울립니다.

### 검증

- 에뮬레이터: 홈 진입 상세 메뉴(신고만) · 제작 진입 상세 메뉴(신고·삭제) · 제작 카드·채팅 카드의 더보기 버튼과 길게 누르기로 여는 다이얼로그 캡처 확인
