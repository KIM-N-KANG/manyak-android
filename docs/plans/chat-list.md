## 목표와 제외 범위

채팅 탭을 빈 화면에서 목록으로 바꾸고, 카드 탭으로 기존 채팅방에 들어가 이어가는 경로를 연다
(FE-SCREEN-004 · FLOW-005). 채팅방 목적지와 `GET /chats/{chatId}` 조회는 이미 동작하므로 이번에
만드는 것은 그 앞의 목록 하나다.

**이번 범위** — `GET /users/me/chats` 배선, `ChatSummary` 도메인 모델, 채팅 목록 화면(카드·골격·빈 상태·
재시도·화면 복귀 갱신·당겨서 새로고침), 카드 탭 채팅방 진입, 빈 상태의 제작 탭 전환 배선, 하네스
매트릭스 갱신.

**제외** — 페이징. 서버가 `limit`(1~100 clamp)만 주고 커서·오프셋이 없어 앱 단독으로 붙일 수 없다
(하네스 §3-3-3 채팅 목록). 채팅 삭제도 제외한다 — 진입점이 채팅방 옵션 메뉴 하나로 확정됐고 그
메뉴는 FE-SCREEN-005 잔여다. 채팅 플레이(입력 컴포저·SSE 턴 진행)는 이번 브랜치와 무관하다.

## 새로 내린 결정

1. **`GET /users/me/chats`는 `UserApi`에 두고 `ChatRepositoryImpl`이 부른다.** 경로가 본인 소유 자원이라
   API 인터페이스는 `UserApi`가 맞고(`myStories`가 이미 그 자리에 있다), 도메인 계약은 채팅 생성·상세와
   한 곳에 있어야 읽히므로 `ChatRepository.myChats()`로 낸다. `StoryRepositoryImpl`이 `StoryApi`와
   `UserApi`를 함께 받는 것과 같은 배치다.

2. **`ChatSummary`는 카드가 그리는 것만 담는다.** `storyId`·`reachedEndings`를 역직렬화하지 않는다 —
   카드는 스토리로 이동하지 않고 엔딩도 표시하지 않는다. `StorySummary`·`StoryDetail`과 같은 원칙이다.

   ```
   ChatSummary(id, storyTitle, thumbnailUrlSm, lastStoryPreview, turnCount, updatedAtEpochMillis)
   ```

3. **웹의 항목 필터를 옮기지 않는다.** 웹은 필수 필드가 하나라도 없으면 항목을 버리는데, 그건 서버
   계약이 아니라 orval이 응답 전 필드를 옵셔널로 뽑은 데 대한 방어다. 앱은 채팅 상세 DTO와 같이 빠진
   값에 기본값을 채우고 항목을 남긴다 — 계약이 깨졌을 때 오류가 아니라 조용히 짧아진 목록으로
   나타나면 사용자는 이어갈 채팅이 사라진 이유를 알 수 없다. **`lastStoryPreview`의 빈 문자열은 정상
   값**(완료 턴이 없는 채팅)이라 필터 대상이 아니고 fallback 문구가 그 자리를 맡는다.

4. **시각은 데이터 계층에서 epoch millis로 바꾸고 상대 시간은 화면이 만든다.** 와이어 형식(ISO 8601
   UTC)을 아는 곳은 데이터 계층이고, "지금"과 기기 시간대·문구를 아는 곳은 화면이다. 파싱이 실패하면
   `null`로 두고 카드가 시각 칩만 그리지 않는다(`createdAt`의 `toDisplayDate()`와 같은 처리).

5. **코어 라이브러리 디슈가링을 켜지 않고 `java.util.Calendar`로 계단을 만든다.** 상대 시간에는
   `분·시간` 산술과 **기기 시간대 기준 달력일 비교**(오늘·어제·n일 전)가 필요하다. `java.time`을 쓰려면
   minSdk 24에서 디슈가링을 켜야 하는데, 이 레포에는 공용 빌드 규약 모듈이 없어 안드로이드 모듈
   열둘의 `build.gradle.kts`를 모두 건드리게 된다 — 얻는 것이 날짜 계산 하나뿐이라 스토리 상세에서
   내린 판단을 그대로 유지한다. 계단 함수는 `now` 를 인자로 받는 순수 함수로 두어 단위 테스트로 경계를 고정한다.

   | 조건 | 표시 |
   | --- | --- |
   | 60초 미만 | 방금 전 |
   | 60분 미만 | n분 전 |
   | 12시간 미만 | n시간 전 |
   | 기기 시간대 기준 같은 날 / 전날 | 오늘 / 어제 |
   | 달력 기준 7일 미만 | n일 전 |
   | 그 이상 | `YYYY-MM-DD`(기기 시간대) |

   마지막 갈래가 스토리 상세 생성일과 갈리는 점을 주의한다 — 상세는 **KST 기준 날짜**를 쓰지만(KNK-1108),
   여기는 웹과 맞추기 위해 **기기 시간대의 날짜**를 쓴다. 상대 시간은 "오늘·어제" 판정부터 기기 시간대를
   따르므로 마지막 갈래만 KST로 바꾸면 같은 목록 안에서 기준이 갈린다.

6. **떠 있는 동안 시각을 다시 세지 않는다.** "3분 전"은 화면에 머무는 사이 뒤처지지만, 1분마다 도는
   타이머를 두면 목록 전체가 주기적으로 다시 그려진다. 값은 조회 결과가 바뀔 때만 다시 계산하고,
   화면 복귀 갱신이 그 자리를 대신한다.

7. **`StoryThumbnail`에서 표지 본체를 떼어낸다.** 지금 컴포넌트는 표지와 턴 수 뱃지를 함께 그리는데,
   채팅 카드의 48dp 표지에는 뱃지를 얹지 않는다(턴 수는 메타 행이 맡고, 그 크기에서는 뱃지가 표지를
   거의 다 덮는다). 뱃지를 끄는 인자를 더하는 대신 표지 본체를 `StoryCover`로 내리고 기존
   `StoryThumbnail`이 그 위에 뱃지를 얹는 형태로 바꾼다 — 기존 호출부 셋은 그대로 두고, 설정 구멍도
   남기지 않는다. 두 번째 사용처가 생겼을 때 공유하는 만큼만 떼어낸다는 규칙 그대로다.

8. **채팅 카드·골격·상대 시간 포매터는 `:feature:chat`에 둔다.** 사용처가 이 화면 하나뿐이라 `:core:ui`로
   올리지 않는다. 사용자에게 보이는 문자열만 규칙대로 `:core:ui`의 `strings.xml`에 둔다.

9. **빈 상태 CTA는 셸이 준 콜백으로 탭을 바꾼다.** 화면은 라우트도 탭도 모르므로 `onGoToStudio: () -> Unit`
   만 받고, `MainTabsScreen`이 자기 `selectedTab`을 바꾼다. 목적지를 push하지 않는 것이 핵심이다 — 탭
   전환은 이력에 쌓이지 않아야 하고, push하면 뒤로가기가 채팅 탭으로 되돌아온다. 탭 화면이 선택 탭을
   바꾸는 첫 사례라 배선을 셸에 남긴다.

10. **`ScreenShown`(ON_START)이 조회를 맡고 `Refresh`가 그것을 취소한다.** 채팅방은 셸 위에 쌓여
    돌아오면 이 화면이 다시 컴포지션에 들어오므로 ON_START가 다시 돌고, ViewModel은 나브 엔트리에
    묶여 살아 있어 목록이 남은 채 조용히 갱신된다(제작 탭과 같은 구조). 당겨서 새로고침은 진행 중인
    조용한 재조회를 취소하고 시작한다 — 명시적 요청이 배경 갱신보다 앞선다.

11. **골격은 카드와 같은 행 구조로 8줄 그린다.** 3:4 표지 + 제목 줄 + 미리보기 줄 + 메타 줄이라 목록이
    도착할 때 자리가 튀지 않는다. 표시 여부는 호출부의 지연 판정(`rememberDelayedProgressVisibility`)이
    정한다. 그리드가 아니라 행이라 첫 화면을 채우는 데 제작 탭(6장)보다 더 필요하다.

12. **오류 문구는 이미 있는 `chat_room_load_error`("채팅을 불러오지 못했어요")를 함께 쓴다.** 3-1이 채팅
    목록과 채팅 화면에 같은 문구를 정의하고 있어 리소스를 두 벌 만들 이유가 없다.

13. **카드의 접근성 이름을 "{제목} 채팅 보기"로 두지 않는다.** 하네스가 처음 적었던 문장을 구현하면서
    뒤집었다. 카드는 `clickable` 이 만드는 하나의 합쳐진 노드라 제목·미리보기·메타가 이어서 읽히는데,
    그 위에 `contentDescription` 으로 이름을 덮으면 **읽히던 내용이 통째로 사라진다.** 이름 대신
    동작 라벨(`onClickLabel`)을 "채팅 보기"로 두어 내용은 그대로 읽히고 무엇을 하는 자리인지도
    드러나게 했다. 제목을 라벨에 다시 넣지 않는 것도 같은 이유다 — 합쳐진 카드가 이미 읽는다.
    하네스 §3-3-3 채팅 목록의 해당 문단도 이 동작으로 고쳤다.

## 자산·합의가 필요한 항목

- ~~달력 아이콘 벡터가 없다.~~ 원본(`calendar-day-outline.svg`)을 받아 `ic_calendar` 로 추가했다.
- **카드 여백·표지 폭의 토큰 확인.** 카드 여백은 웹과 같은 가로 16px·세로 8px이고 기존 토큰
  (`spacing.gutter`·`spacing.compact`)으로 그대로 떨어져 `DESIGN.md` 갱신은 필요하지 않았다.
  **표지 폭만 웹(48px)과 갈려 52dp 다** — 화면에서 보고 키운 값이며, 카드 높이도 3:4 비율을 따라
  약 69dp 로 함께 늘어난다. 표지 모서리는 스토리 카드와 같은 `shapes.thumbnail`(12dp)을 쓴다 —
  이 크기에서는 웹의 `rounded-sm` 보다 둥글지만, 같은 표지 컴포넌트가 화면마다 다른 모서리를
  갖지 않는 쪽을 택했다.

## 구현 순서

1. `:core:domain` — `ChatSummary`, `ChatRepository.myChats()`
2. `:core:data` — `UserApi.myChats()`, `ChatSummaryDto`·매핑(ISO 8601 UTC → epoch millis),
   `ChatRepositoryImpl` 구현 *(3번과 병렬 가능)*
3. `:core:ui` — `StoryThumbnail`에서 `StoryCover` 분리, `ic_calendar` 추가, 문자열 리소스
4. `:feature:chat` — `ChatListViewModel`(MVI), `ChatListScreen`, `ChatCard`, `ChatListSkeleton`,
   상대 시간 포매터
5. `:app` — `MainTabsScreen`·`MainTabsContent`에 `onOpenChat`·`onGoToStudio` 배선, `ManyakApp`에서
   `ChatRoomRoute(chatId)` push
6. 단위 테스트 — ViewModel(서버 순서 유지 · 복귀 갱신이 골격을 깔지 않음 · 새로고침이 조용한 재조회를
   취소 · 첫 조회 실패와 갱신 실패 분기), 상대 시간 계단 여섯 경계, DTO 매핑(빈 미리보기 · null 썸네일 ·
   시각 파싱 실패)
7. 하네스 매트릭스 현재 상태 갱신 — FE-SCREEN-004 두 행, FLOW-005
