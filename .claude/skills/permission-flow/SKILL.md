# 런타임 권한 흐름

## 먼저 확인할 것

- 권한 없이 시스템 선택기나 축소 기능으로 목적을 달성할 수 있는지 확인합니다.
- 필요한 권한과 OS 버전 범위를 실제 manifest와 SDK 계약에서 확인합니다.
- 알림 권한의 요청 시점과 채널 정책은 `notification-entry`에서 결정합니다.

## 상태와 요청

시스템 권한 상태만으로 최초 요청 전과 다시 요청할 수 없는 상태를 항상 구분할 수 있다고 가정하지 않습니다. 앱은 권한 허용 여부를 복제 저장하지 않되, 요청 이력처럼 흐름 판정에 필요한 최소 메타데이터를 둘 수 있습니다.

- 사용자가 권한이 필요한 행동을 시작한 맥락에서 요청합니다.
- 사전 설명에서 취소할 수 있게 하고 취소를 시스템 거부로 기록하지 않습니다.
- 다시 요청할 수 있으면 필요 이유와 재시도 수단을 제공합니다.
- 시스템 대화상자를 더 띄울 수 없는 상태에서는 반복 요청 대신 설정 화면과 켜야 할 항목을 안내합니다.
- 설정에서 복귀하거나 앱이 다시 활성화되면 실제 권한 상태를 다시 읽습니다.

## 축소 경로

거부 상태에서도 가능한 기능을 명시합니다. 권한 없이는 기능이 성립하지 않는다면 빈 화면이나 무반응 대신 제한 이유와 빠져나갈 경로를 제공합니다.

## 검증 경계

이 스킬은 기기 검증을 직접 실행하지 않습니다. `permission` 위험 태그와 변경된 분기만 `android-change-verification`에 전달합니다.

- 로컬에서는 바뀐 거부·복귀 분기만 확인합니다.
- 최소·최신 OS 전체 흐름은 계측 테스트 또는 릴리스 QA 매트릭스에서 수행합니다.
- 실행하지 않은 버전·기기 조합을 통과로 보고하지 않습니다.
